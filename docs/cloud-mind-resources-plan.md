# 课程资源工坊 · 提升方案

> 云端智囊六功能之一。六功能里"能跑但藏着雷"的一个：最大问题不是慢，是 **失败偷偷给你假货 + 六样一锅端**。

## 0. 一句话定位
信任底线被"静默降级假货"击穿 + 性能被"6 类一次全生成"拖垮。先把"生成真货、按需单生成"修对，再做 RAG 供给。

## 1. 现状
- 6 类资源：讲义/PPT/导图/题库/实操/视频脚本；生成后"阅读/复制/下载 Markdown"，2s 轮询恢复后台任务。
- 流程：安全检查 → 画像构建 → 资料检索 → 资源生成 → 内容检查 → 学习路径。LLM 单次 `callLLM`（25s/重试×1）。
- RAG 检索 `data/course-knowledge/ai-intro`；个性化来自输入+对话信号+学习记录。
- 复用度低；落她仅 Markdown/磁盘 JSON，**未入库、未成为其它功能 RAG 素材源**。

## 2. 短板与取舍
| 优先级 | 事项 | 说明 |
|---|---|---|
| **P0** | **生成失败绝不再静默降级到 demo 假资源**（`lib/software-cup/demo-service.ts`） | 现失败悄悄返回演示假料，学生拿到假讲义却不知情——比搜题"给错答案"更隐蔽。改"明确报错+允许重试"，无 tradeoff |
| **P0** | **先选类型再单生成**（现 6 类一次全生成） | 单线程串行、超时长难完成、用户只要一样却等六样。与出题"先选题型"同逻辑 |
| P1 | 流式 `/stream` 接口修好（现 410） | 属性能基线统一流式管道 |
| P1/P2 | 打通资源工坊 → 授课/出题 RAG 素材供给 | 前置依赖上两条；让产物进可复用素材库，补授课缺的 RAG |

## 3. 优先级行动
| 优先级 | 事项 |
|---|---|
| P0 | 移除"失败降级 demo"逻辑 → 明确报错 + 可重试 + 保留原输入 |
| P0 | 流程改为"用户先选 1 类资源 → 单独生成该类" |
| P1 | 修复流式接口（410）|
| P1/P2 | 产物入库 / 作为共享 RAG 素材源 |

## 4. 测试方法
- **防假货（自动化关键）**：mock LLM 失败 / 超时 / 返回非法 JSON → 断言**绝不返回 demo 资源**；而是错误态 + 可重试按钮；输入不丢失。
- **按需单生成（组件）**：仅选"讲义"→ 只生成讲义一种，不触发其它 5 种；结果正确渲染为 Markdown。
- **流式（自动）**：mock 分块返回 → 断言首块可见进度与内容（修复 410 后）。
- **链路集成（补测）**：API 路由 / Runner / Job Store / Quality Review 全链路；失败、重试、持久化恢复。
- **回归**：既有 `tests/sky/course-studio-*.test.tsx` 等不回归。
