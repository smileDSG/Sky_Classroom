### 2.2 C-001 题目分析 Agent（Week 2）

#### 目标
输入题目文本（+可选图片），输出 `{ subject, knowledgePoints[], difficulty, questionType, confidence }`

> 📌 **与现有代码的关系**：当前 `classifyProblem()`（`lib/solve/solver-constants.ts:43`）使用关键词启发式路由（science/humanities/universal），仅覆盖 3 类。C-001 的 LLM 分析 Agent 是升级版，覆盖 9 学科+4 题型+知识点+难度。完成后，`classifyProblem()` 应改为调用 `analyze-agent` 的轻量封装，关键词逻辑作为 LLM 不可用时的兜底。

#### 产出文件

| 文件 | 路径 | 说明 |
|------|------|------|
| `analyze-agent.ts` | `lib/solve/agents/` | Agent 主类，封装 LLM 调用 |
| `analyze-prompts.ts` | `lib/solve/agents/` | 分析 prompt 模板 |
| `analyze-types.ts` | `lib/solve/agents/` | 类型定义 |

#### 类型设计

```typescript
// analyze-types.ts
export type Subject = 'math' | 'physics' | 'chemistry' | 'biology' 
  | 'chinese' | 'english' | 'history' | 'geography' | 'politics';

export type Difficulty = 'easy' | 'medium' | 'hard';

export type QuestionType = 'choice' | 'fill' | 'solve' | 'judge';

export interface AnalysisResult {
  subject: Subject;
  knowledgePoints: string[];      // 2-4 个知识点
  difficulty: Difficulty;
  questionType: QuestionType;
  confidence: number;             // 0~1
}
```

#### 开发步骤

1. **Day 1**：定义类型 + 编写 prompt 模板（`analyze-prompts.ts`）
   - prompt 需覆盖所有 9 个学科、4 种题型的识别规则
   - 输出格式强制 JSON（function calling 或 JSON mode）
2. **Day 2**：实现 Agent 主类（`analyze-agent.ts`）
   - 使用轻量模型（DeepSeek Flash）保证响应速度
   - 支持纯文本输入 + 图片 URL 输入
   - 返回类型安全的 `AnalysisResult`
   - **同时导出 `classifyProblemFromAnalysis` 函数**，供 `solver-constants.ts` 调用，替换现有关键词路由
3. **Day 3**：自测 + 边界 case 处理
   - 多学科混合题目（如物理+数学公式）
   - 纯图片题目
   - 低置信度处理（confidence < 0.5 时标记需人工确认）

#### 检验标准

- [ ] 数学/物理/化学/生物/语文/英语/历史/地理/政治 9 个学科识别准确
- [ ] 知识点提取 2-4 个
- [ ] 难度评估 easy/medium/hard 合理
- [ ] 题型判断 choice/fill/solve/judge 准确
- [ ] 响应时间 ≤ 3s（使用轻量模型）
- [ ] `classifyProblem()` 能调用 analyze-agent 并正确路由到 science/humanities/universal

### 2.3 C-002 自校验 Agent（Week 2-3）

#### 目标
输入题目 + 原始答案，独立验证答案正确性，错误时返回修正建议

#### 产出文件

| 文件 | 路径 | 说明 |
|------|------|------|
| `verify-agent.ts` | `lib/solve/agents/` | 校验 Agent 主类（含 `VerificationResult` 类型定义） |
| `verify-prompts.ts` | `lib/solve/agents/` | 校验 prompt 模板 |
| `answer-matcher.ts` | `lib/solve/agents/` | 答案格式匹配工具 |

> 📌 **与原计划一致**：`VerificationResult` 类型直接定义在 `verify-agent.ts` 中，不单独建 `verify-types.ts` 文件。

#### 类型设计（内联在 verify-agent.ts 中）

```typescript
export interface VerificationResult {
  isCorrect: boolean;
  confidence: number;             // 0~1
  suggestedAnswer?: string;       // isCorrect=false 时返回
  reasoning: string;              // 校验推理过程
}
```

#### 开发步骤

1. **Day 1**：编写答案匹配器（`answer-matcher.ts`）
   - 处理 LaTeX 格式差异：`$3$` vs `3` vs `\\(3\\)`
   - 处理选项格式差异：`A` vs `A.` vs `答案:A`
   - 处理数值精度差异：`3.14` vs `3.14159`
   - 处理多答案情况（如集合 `{1,2}` vs `{2,1}`）
2. **Day 2**：编写校验 prompt + Agent（`verify-agent.ts`）
   - 使用高精度模型（DeepSeek V4）
   - 模型独立解题 → 与原始答案对比 → 输出 `VerificationResult`
3. **Day 3**：联调 + 边界 case
   - 正确答案通过
   - 错误答案被拦截并返回 suggestedAnswer
   - 格式差异正确识别为相同答案

#### 检验标准

- [ ] 正确答案 100% 通过（不误杀）
- [ ] 错误答案被正确拦截
- [ ] LaTeX/选项/数值格式差异处理正确
- [ ] 使用独立模型（不同于解题 Agent）

### 2.4 C-003 解题 Agent 链调度器（Week 3）

#### 目标
串联 analyze → solve → verify → (correct?) → knowledge → similar，含修正逻辑

> 📌 **与现有代码的关系**：
> - 当前 `explain-stream/route.ts` 已有完整的 5 阶段流程（check bank/cache → route → streamSolve → fill missing → auto-save）。C-003 的 `solve-chain.ts` 是在此基础上**嵌入 analyze 和 verify/correct 步骤**，不是从零重写整个路由。
> - **解题步骤复用** `streamSolve`（`lib/solve/streaming-solver.ts`），不要裸调 LLM。该函数已含 LaTeX JSON 修复、流式解析等完整实现。
> - **知识点步骤复用** `buildKnowledgePointsPrompt`（`lib/solve/solver-prompts.ts:101`）。
> - **类似题步骤复用** `findSimilarByKnowledgePoints`（`lib/solve/question-bank.ts:189`）。

#### 产出文件

| 文件 | 路径 | 说明 |
|------|------|------|
| `solve-chain.ts` | `lib/solve/` | 链式调度器主文件 |
| `correct-agent.ts` | `lib/solve/agents/` | 修正 Agent |
| `correct-prompts.ts` | `lib/solve/agents/` | 修正 prompt |

#### 链路流程

```
输入题目文本
    │
    ▼
[1] analyze-agent ───→ 输出 { subject, knowledgePoints, difficulty, questionType }  【全新】
    │
    ▼
[2] solve-agent ─────→ 调用 streamSolve() 复用现有解题逻辑                   【复用 streamSolve】
    │
    ▼
[3] verify-agent ────→ 输出 { isCorrect, suggestedAnswer? }                  【全新】
    │
    ├─ isCorrect=false → [4] correct-agent（最多1次修正，使用不同模型）
    │                        │
    │                        ▼
    │                   修正答案 ──→ 返回修正结果                             【全新】
    │
    ▼ (isCorrect=true 或修正后)
[5] knowledge-agent ─→ 调用 buildKnowledgePointsPrompt 生成知识点            【复用已有 prompt】
    │
    ▼
[6] similar-agent ───→ 调用 findSimilarByKnowledgePoints 检索类似题          【复用已有函数】
    │
    ▼
输出完整 SolveResult
```

> 📌 **标注说明**：【全新】= 需要新编写的代码；【复用】= 调用已有函数，无需重新实现。

#### 开发步骤

1. **Day 1**：实现 solve-chain.ts 主流程
   - 按顺序调用各 Agent
   - 每一步结果存入共享上下文，传递给后续 Agent
   - 超时控制：单步 30s，总链路 60s
2. **Day 2**：实现 correct-agent + 修正逻辑
   - verify 返回 `isCorrect=false` 时触发
   - correct-agent 使用不同于 solve-agent 的模型
   - 最多修正 1 次，超过仍错误则标记"答案存疑"
3. **Day 3**：错误降级 + 集成测试
   - 单步失败不阻塞后续步骤（跳过 + 标记 warning）
   - 全链路跑通：正常链路 / 修正链路 / 超时降级链路

#### 检验标准

- [ ] 正常链路：analyze → solve → verify → knowledge → similar 完整执行
- [ ] 修正链路：verify 失败 → correct → 继续 knowledge → similar
- [ ] 超时降级：单步超时被跳过，后续步骤继续执行
- [ ] 单步超时 ≤ 30s，总链路超时 ≤ 60s

### 2.5 C-004 解题 SSE 流式事件（Week 4）

#### 目标
重构 `POST /api/sky/solve/explain-stream`，使用新链路，每个 Agent 完成后立即推送

> 📌 **与现有代码的关系**：当前 `explain-stream/route.ts` 已有两套 SSE 格式化函数：
> - `formatStreamEvent(event: StreamEvent)` — 来自 `streaming-solver`，格式为 `data: {type, ...rest}\n\n`
> - `formatSSEEvent(type, data)` — 本地封装，格式相同
>
> 新事件（`analysis`、`verification`、`correcting`）应使用 `formatSSEEvent` 封装，与现有 `phase`/`step`/`answer`/`knowledge`/`similar`/`done` 格式一致。旧前端不识别新事件类型会直接忽略，向后兼容自动保证。

#### 产出文件

| 文件 | 路径 | 说明 |
|------|------|------|
| `route.ts` | `app/api/sky/solve/explain-stream/` | SSE 端点，接入 solve-chain |

#### SSE 事件类型

| 事件名 | 数据 | 时机 | 新旧 |
|--------|------|------|------|
| `phase` | `{ phase: 'analyzing' \| 'solving' \| 'verifying' \| 'correcting' \| 'knowledge' \| 'similar' \| 'done' }` | 每个阶段开始时 | 扩展：新增 analyzing/verifying/correcting |
| `analysis` | `AnalysisResult` | 分析完成时 | **新增** |
| `step` | `{ stepIndex, content, isStreaming }` | 解题步骤流式推送 | 现有（保持格式） |
| `answer` | `{ answer, isCorrect }` | 答案确定时 | 扩展：增加 isCorrect |
| `verification` | `VerificationResult` | 校验完成时 | **新增** |
| `knowledge` | `{ knowledgePoints[] }` | 知识点提取完成时 | 现有（保持格式） |
| `similar` | `{ questions[] }` | 类似题检索完成时 | 现有（保持格式） |
| `done` | `{ metadata: { duration, stepsCompleted, hasCorrection } }` | 全链路完成时 | 扩展：增加 hasCorrection |
| `error` | `{ step, message }` | 某步骤失败时 | 现有（保持格式） |

#### 开发步骤

1. **Day 1**：重写 explain-stream/route.ts
   - 接入 solve-chain，监听每个阶段完成事件
   - 新增事件（analysis/verification）使用 `formatSSEEvent` 封装，与现有格式一致
   - 保留现有的 question bank / solve cache 检查逻辑（优先命中缓存时不走新链路）
2. **Day 2**：流式输出优化
   - 不等全部完成，逐阶段推送
   - 错误事件处理

#### 检验标准

- [ ] 每个 Agent 完成后立即推送对应事件
- [ ] 事件顺序正确：phase → analysis → step → answer → verification → knowledge → similar → done
- [ ] 旧前端兼容（不解析的新事件被忽略）

| 掌握度 | 深度 | 策略 |
|--------|------|------|
| < 30% | basic | 基础概念讲解，类比举例，详细推导 |
| 30-70% | intermediate | 重点强化，易错点提醒，变式训练 |
| > 70% | advanced | 拓展提升，综合应用，竞赛级题目 |

#### 开发步骤

1. **Day 1**：定义类型 + 编写规划 prompt
   - 输入 StudentProfile + 授课主题
   - 输出 LessonPlan，含多个 Section
2. **Day 2**：实现规划逻辑
   - 根据掌握度调整每个 Section 的 depth
   - 薄弱点（weakPoints）优先安排
   - 每个知识节点后插入随堂测

#### 检验标准

- [ ] 掌握度 < 30% 时生成基础内容
- [ ] 掌握度 30-70% 时生成强化内容
- [ ] 掌握度 > 70% 时生成拓展内容
- [ ] 薄弱点优先安排
- [ ] 每个知识节点后有随堂测规划

### 3.4 D-003 动态授课内容生成（Week 6）

#### 开发步骤

   - `POST /api/sky/teaching/generate-stream`
   - 逐 Section 推送，不等全部内容完成

### 3.5 D-004 随堂检测系统（Week 6-7）

#### 产出文件

| 文件 | 路径 | 说明 |

| `quiz-injector.ts` | `lib/teaching/` | 随堂测注入器 |
| `inline-quiz.tsx` | `components/sky/teaching/` | 内嵌答题组件 |

#### 开发步骤

1. **Day 1**：实现 quiz-injector
   - 每个知识点后自动生成 1-2 道检测题
   - **优先从题库检索**（复用 `findSimilarByKnowledgePoints`），不足部分 AI 生成
   - 题目难度根据 StudentProfile 掌握度动态调整
2. **Day 2**：前端答题组件
   - 内嵌在授课内容中
   - 答题交互 + 即时批改 + 解析展示
   - **批改复用现有 `grading` agent prompt**（`lib/solve/solver-prompts.ts` 中的 grading 模板）
3. **Day 3**：掌握度更新 + 内容调整
   - 答对/答错更新 StudentProfile
   - 答对率低 → 补充讲解
   - 答对率高 → 加速进入下一节

#### 检验标准

- [ ] 每个知识点后有 1-2 道检测题
- [ ] 答题后立即批改 + 解析
- [ ] 答对率更新 StudentProfile
- [ ] 内容根据答题结果实时调整
