# 摘星锦囊冗余梳理

> 模块：摘星锦囊首页（`app/sky/page.tsx`）
> 目标：减少重复入口、重复数据面板和重复状态请求，让首页从“信息堆叠”回到“学习调度入口”。
> 结论：摘星锦囊应保留轻量总览和今日行动，把深度学情下沉到天梯工坊，把具体 AI 生成流程交给云端智囊。

## 一、产品定位

摘星锦囊当前已经具备学习首页的基础能力：问候语、每日建议、统计卡片、学习路径、连续打卡、云端智囊入口、趋势图、能力雷达和最近活动。

下一阶段不建议继续增加模块，而应做减法。首页的核心问题不是“信息不足”，而是多个区域同时承担“引导用户下一步”的职责，导致行动优先级变弱。

建议定位：

| 模块 | 核心职责 | 首页中的呈现 |
|------|----------|--------------|
| 摘星锦囊 | 学习总览、今日主行动、关键入口 | 只回答“我现在该做什么” |
| 云端智囊 | AI 工具集和个性化生成 | 保留工具入口，不展示完整学情 |
| 天梯工坊 | 学情画像、错题、复习、知识图谱、成长路径 | 承载深度数据和分析 |

## 二、冗余清单

### 2.1 功能入口重复

当前摘星锦囊中有多组入口都在做“跳转到功能页”：

| 区域 | 当前职责 | 冗余点 |
|------|----------|--------|
| `CloudMindMiniCard` | 拍照搜题、幻灯片、记忆卡片入口 | 与空状态 quick actions 和部分快捷操作重复 |
| `QuickActionsCompact` | 学习路径、数据分析、复习计划入口 | 与学习路径卡、统计区、天梯工坊入口职责重叠 |
| `DashboardEmptyState` quick actions | 新用户功能入口 | 与正常态工具入口不是同一套信息架构 |
| 顶部问候区 | 展示当前状态和轻量激励 | 也在表达“继续学习”，与每日建议抢主行动 |

建议：

1. 保留一组主工具入口，优先使用 `CloudMindMiniCard` 或升级后的“云端智囊工具入口”。
2. 删除或合并 `QuickActionsCompact`，把“学习路径”和“复习计划”交给对应业务卡片。
3. 空状态复用同一套主入口配置，不再维护另一套 quick actions。
4. 顶部问候区只做情绪和状态承接，不承担主要行动分发。

### 2.2 数据展示重复

多个卡片都在表达“学得怎么样”：

| 区域 | 展示内容 | 冗余点 |
|------|----------|--------|
| `StatCards` | 今日搜题、待复习、知识掌握度 | 已覆盖核心状态 |
| 连续打卡卡片 | streak days 和里程碑 | 与顶部 streak badge、学习统计有重叠 |
| `LearningTrendChart` | 近 14 天错题和复习趋势 | 更适合学情页，不一定需要首页常驻 |
| `AbilityRadar` | 知识能力分布 | 属于深度画像，更适合天梯工坊 |
| `ActivityTimeline` | 最近错题活动 | 与错题/复习管理页有边界重叠 |

建议：

| 处理方式 | 内容 |
|----------|------|
| 保留 | 每日建议、3 个核心统计、学习路径/今日主行动 |
| 弱化 | 连续打卡，只保留小型目标提示或并入统计区 |
| 下沉 | 能力雷达、完整趋势图、最近活动详情 |
| 可选保留 | 最近活动只保留 3 条，并作为“继续复习”的入口 |

首页应避免变成完整报表。完整趋势、雷达、活动详情建议进入 `/sky/learning`。

### 2.3 状态请求重复

当前学习统计被多个位置各自请求：

| 文件 | 请求 |
|------|------|
| `app/sky/page.tsx` | `fetch('/api/sky/learning-stats')` |
| `components/sky/dashboard/daily-suggest-card.tsx` | 再次 `fetch('/api/sky/learning-stats')` |
| `components/sky/dashboard/streak-milestone.tsx` | 独立请求 `learning-stats`，但页面当前没有直接使用该组件 |

建议：

1. 由 `app/sky/page.tsx` 统一请求首页所需状态。
2. `DailySuggestCard` 改为接收 `stats` 或 `PersonalizationContext`，不要自己再请求。
3. 如果保留 streak 组件，使用父组件传入数据；如果不用，移除未使用组件。
4. 后续可以将首页状态收敛为一个轻量 view model，例如 `StarTipsDashboardModel`。

### 2.4 交互逻辑重复或失效

`lib/mistakes/suggestions.ts` 最后固定 `return suggestions.slice(0, 3)`，而 `DailySuggestCard` 中仍保留“换一批”逻辑。

这会造成一个实际问题：建议生成器最多返回 3 条，组件里 `allSuggestions.length > 3` 很难成立，“换一批”按钮基本没有机会出现。

建议二选一：

| 方案 | 做法 | 适用场景 |
|------|------|----------|
| 删除换一批 | 只展示最多 3 条今日建议 | 首页追求清爽、确定性 |
| 保留换一批 | `generateSuggestions` 返回完整列表，由组件负责分页 | 希望建议池更丰富 |

推荐删除“换一批”，改成一个更强的“今日主行动”。首页不需要像信息流一样轮播建议，学生更需要明确的一步。

### 2.5 路由入口不够统一

项目中同时存在：

| 路由 | 说明 |
|------|------|
| `/sky/solve` | 拍照搜题主入口 |
| `/sky/cloud-mind/solve` | 云端智囊下的拍照搜题入口 |
| `/sky/slides` | 幻灯片相关入口 |
| `/sky/cloud-mind/slides` | 云端智囊下的课件入口 |

如果两个入口体验不同，需要明确主从关系；如果只是包装层不同，则首页应只指向一个主入口。

建议：

1. 摘星锦囊统一指向用户最稳定的主入口。
2. 云端智囊内部再承接工具集合和个性化默认参数。
3. 避免首页同时出现 `/sky/solve` 与 `/sky/cloud-mind/solve` 两种入口。

## 三、建议保留的信息架构

推荐首页结构：

```text
摘星锦囊
  顶部问候与轻状态
  今日主行动
    - 继续复习 / 开始诊断 / 继续学习路径 / 使用推荐工具
  关键统计
    - 今日学习
    - 待复习
    - 掌握度
  学习路径摘要
    - 当前节点
    - 下一步按钮
  云端智囊工具入口
    - 拍照搜题
    - 智能出题
    - 记忆卡片
    - 智能授课
    - 课件生成
```

可下沉到天梯工坊：

```text
天梯工坊
  趋势图
  能力雷达
  最近活动完整列表
  错题详情
  复习队列
  知识图谱
```

## 四、清理优先级

### P0：先修正交互和状态冗余

1. `DailySuggestCard` 不再自行请求 `learning-stats`。
2. 修正 `generateSuggestions` 与“换一批”之间的冲突。
3. 清理未使用或重复的 streak 展示方式。
4. 统一 `/sky/solve` 与 `/sky/cloud-mind/solve` 在首页中的指向。

### P1：收敛首页模块

1. 合并 `CloudMindMiniCard` 与 `QuickActionsCompact` 的入口职责。
2. 空状态复用统一工具入口配置。
3. 将能力雷达和趋势图改为摘要或入口，不在首页常驻展开。

### P2：引入统一个性化上下文

1. 让首页建议读取 `/api/sky/cloud-mind/personalization-context`。
2. 用 `recommendation` 字段生成“今日主行动”。
3. 首页只展示轻量原因，完整分析跳转到天梯工坊。

## 五、验收标准

清理完成后，摘星锦囊应满足：

1. 首屏只有一个最强主行动。
2. 同类功能入口不重复出现。
3. 学习统计只请求一次，并通过 props 或统一 model 分发。
4. 首页不展示完整学情报表，只展示摘要和入口。
5. 空状态和正常态使用一致的信息架构。
6. 每个可点击入口都有明确的产品归属：摘星锦囊、云端智囊或天梯工坊。

## 六、取舍原则

1. 如果一个模块回答“我学得怎么样”，优先放天梯工坊。
2. 如果一个模块回答“我现在该做什么”，优先放摘星锦囊。
3. 如果一个模块启动 AI 生成流程，优先放云端智囊。
4. 首页不追求信息完整，追求行动明确。
5. 重复入口保留用户最熟悉、路径最短、状态最稳定的那个。

## 七、建议结论

摘星锦囊目前的主要冗余不是单个组件写得多，而是多个组件在争夺同一个职责：引导学生下一步。

建议把首页压缩成“今日主行动 + 核心统计 + 学习路径摘要 + 统一工具入口”。这样既保留学习氛围，也能减少用户选择压力，并让云端智囊和天梯工坊各自承担更清晰的产品边界。
