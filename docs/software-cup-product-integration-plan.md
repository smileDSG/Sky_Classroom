# 软件杯能力产品融合方案

> 目标：把软件杯赛题要求转化为天空课堂的自然产品能力，而不是新增一个突兀的“软件杯”栏目。  
> 适用项目：天空课堂 / Sky Classroom  
> 当前结论：学习画像做成全局底座，课程资源生成放入云端智囊，学习路径沿用天梯工坊，完整闭环沉淀为学习实验室。

---

## 一、为什么不能单独放“软件杯”

当前已经完成的软件杯演示页覆盖了赛题硬性要求，但它作为一级导航存在时，会产生三个问题：

1. **产品语义突兀**
   “软件杯”是比赛语境，不是学生使用产品时会主动寻找的学习功能。用户进入天空课堂时更关心“我今天学什么”“怎么生成资料”“哪里看学情”，而不是“软件杯”。

2. **和现有模块重复**
   项目中已经有：
   - `天梯工坊`：学情分析、错题、复习、知识图谱、学习统计。
   - `云端智囊`：拍照搜题、PPT 生成、智能出题、记忆卡片、智能授课。
   - 首页仪表盘：今日推荐、学习趋势、学习路径。
   - `学习实验室 /sky/study-lab`：已经具备“画像 → 资源 → 路径 → 审核”的综合工作台雏形。

   如果再新增一个“软件杯”一级入口，会像临时拼接出来的比赛展示页。

3. **后续扩展不顺**
   软件杯能力本质上不是一个独立功能，而是一组横跨学习平台的底层能力：
   - 学习画像
   - 课程知识库
   - 资源生成
   - 学习路径
   - 安全审核
   - 学习效果评估

   这些能力应该被拆进原有产品结构，而不是集中堆在一个页面。

---

## 二、融合原则

### 2.1 UI 不出现“软件杯”

“软件杯”保留在文档、答辩稿和提交材料中，前端界面不作为用户可见栏目展示。

需要替换的文案：

| 当前文案 | 建议文案 |
| --- | --- |
| 软件杯 | 学习实验室 / 课程资源工坊 |
| 软件杯演示闭环 | 学习闭环 |
| 运行闭环 | 生成学习方案 |
| 多智能体个性化学习资源生成系统 | 课程学习资源工坊 |
| 6/6 阶段完成 | 生成完成 / 学习方案已生成 |
| 比赛演示 | 示例课程 / AI 导论学习方案 |

### 2.2 保持现有产品分工

不要把所有软件杯能力都塞进 `天梯工坊`。更自然的分工是：

| 产品区域 | 职责 | 软件杯能力落点 |
| --- | --- | --- |
| 首页 `/sky` | 总览、今日行动、用户刚进入时的方向感 | 学习画像摘要、今日推荐、路径入口 |
| 天梯工坊 `/sky/learning` | 学习管理、诊断、错题、复习、统计、路径 | 学情画像、学习路径、学习效果评估 |
| 云端智囊 `/sky/cloud-mind` | AI 工具集合 | 课程资源生成工具 |
| 学习实验室 `/sky/study-lab` | 跨模块完整闭环展示 | 画像、知识库、资源、路径、安全审核的综合工作台 |
| 文档 `docs/software-cup-*` | 比赛说明、提交材料 | 赛题映射、开源合规、防幻觉说明 |

### 2.3 赛题能力变成“系统能力”

答辩时可以说：

> 我们没有把软件杯要求做成一个独立专区，而是将其融入天空课堂的核心学习链路：学习画像是全局底座，云端智囊负责生成多模态课程资源，天梯工坊负责路径规划和效果评估，学习实验室用于串联完整闭环。

## 三、推荐信息架构

### 3.1 顶部导航

保留现有产品导航，移除 `软件杯` 一级入口。

推荐结构：

```text
天穹授课
摘星锦囊
云端智囊
天梯工坊
云翼助手
```

不推荐：

```text
天穹授课
摘星锦囊
云端智囊
天梯工坊
云翼助手
软件杯
```

原因：`软件杯` 是提交背景，不是产品能力名称。

### 3.2 首页 `/sky`

首页应该承担“刚进入页面就知道系统懂我”的作用。建议新增或强化一个学习画像摘要区。

建议模块名：

```text
我的学习画像
```

展示内容：

- 当前画像完整度。
- 当前薄弱点。
- 当前学习目标。
- 推荐学习方式。
- 今日建议行动。

按钮：

- `完善画像`
- `生成今日学习方案`
- `进入学习实验室`

空状态文案：

```text
先告诉我你的专业、课程目标和薄弱点，我会生成你的学习画像，并为你推荐学习路径和资源。
```

这能自然承接赛题中的“对话式学习画像自主构建”。

### 3.3 天梯工坊 `/sky/learning`

天梯工坊不应该成为所有功能的堆放处，它更适合作为学习管理中心。

保留和强化：

- 错题本
- 复习计划
- 知识图谱
- 学习统计
- 学情分析
- 学习路径

新增一个入口卡片即可：

```text
学习实验室
串联画像、知识库、资源生成、路径规划和安全审核，查看完整个性化学习闭环。
按钮：进入实验室
```

另一个入口：

```text
生成课程资源
根据当前画像和薄弱点，进入云端智囊生成讲义、题库、PPT、代码案例。
按钮：打开课程资源工坊
```

天梯工坊只负责判断“应该学什么”，不直接承担大规模资源生成。

### 3.4 云端智囊 `/sky/cloud-mind`

云端智囊是 AI 工具集合，因此课程资源生成应该放在这里。

新增工具：

```text
课程资源工坊
基于课程知识库和学习画像，生成讲义、PPT、题库、思维导图、代码案例和视频脚本。
```

推荐路由：

```text
/sky/cloud-mind/course-studio
```

工具卡片与现有工具并列：

```text
拍照搜题
PPT课件生成
智能出题
记忆卡片
智能授课
课程资源工坊
```

课程资源工坊内部结构：

```text
左侧：课程与学习需求
中间：Agent 生成进度与资源卡片
右侧：课程知识库命中、安全审核、推荐去向
```

默认课程：

```text
《人工智能导论》
```

后续可扩展为课程选择器：

```text
人工智能导论
数据结构
计算机网络
数据库系统
机器学习
```

### 3.5 学习实验室 `/sky/study-lab`

项目已经存在 `StudyLabPage`，它非常适合承接软件杯完整闭环。

建议定位：

```text
学习实验室 = 个性化学习闭环工作台
```

页面展示：

- 今日任务
- 学习画像摘要
- 课程知识库命中
- 学习路径
- 多模态资源
- 防幻觉与安全审核

这部分可以作为答辩主演示页，但不需要出现在一级导航中。

推荐入口：

- 首页画像卡片：`进入学习实验室`
- 天梯工坊入口卡片：`进入实验室`
- 答辩时直接打开 `/sky/study-lab`

## 四、软件杯功能拆分映射

### 4.1 对话式学习画像

赛题要求：

> 通过自然语言对话自动抽取特征，构建不少于 6 个维度的动态学生画像，并支持随学随新。

产品融合方式：

- 首页展示画像摘要。
- 天梯工坊保留完整学情分析。
- `/api/sky/student/profile/conversation` 作为画像构建接口。
- 画像数据被云端智囊工具调用，用于个性化资源生成。

推荐用户路径：

```text
进入首页
→ 看到“我的学习画像”
→ 输入专业、目标、薄弱点
→ 生成画像
→ 首页和天梯工坊同步更新
```

### 4.2 多智能体资源生成

赛题要求：

> 多智能体协同生成至少 5 种个性化资源。

产品融合方式：

- 新增云端智囊工具：课程资源工坊。
- 不在天梯工坊中直接展开复杂生成流程。
- 资源类型作为工具输出卡片展示。

资源类型：

- 课程讲义
- PPT 大纲
- 思维导图
- 题库
- 代码实操案例
- 视频/动画脚本

推荐用户路径：

```text
云端智囊
→ 课程资源工坊
→ 选择《人工智能导论》
→ 输入学习需求
→ Agent 协同生成资源
→ 一键加入学习路径或复习计划
```

### 4.3 个性化学习路径

赛题要求：

> 结合画像、进度、掌握情况和偏好规划动态学习路径。

产品融合方式：

- 不新建第二套路径系统。
- 沿用已有学习路径能力：
  - `components/sky/dashboard/learning-path-card.tsx`
  - `/api/sky/learning-path`
  - `/api/sky/learning-path/preview`
  - `lib/teaching/learning-path-engine.ts`

增强点：

- 路径生成时可以接入课程资源工坊生成的资源。
- 路径节点展示“推荐资源”。
- 路径节点可跳转到云端智囊工具继续学习。

推荐用户路径：

```text
首页学习路径卡片
→ 生成/查看个性化学习路径
→ 节点推荐课程资源
→ 跳转云端智囊生成或查看资料
```

### 4.4 智能辅导

赛题可选加分：

> 学习过程中遇到问题时，提供即时、多模态答疑。

产品融合方式：

- 保留在 `云翼助手` 和 `云端智囊 / 智能授课` 中。
- 课程资源工坊生成的资源卡片可以提供“问助手”按钮。

按钮示例：

```text
问云翼助手
继续讲解
生成练习
```

### 4.5 学习效果评估

赛题可选加分：

> 跟踪学习行为、练习测试、资源反馈，动态调整策略。

产品融合方式：

- 保留在天梯工坊：
  - 学习统计
  - 错题本
  - 复习计划
  - 学情分析
- 课程资源工坊生成题库后，可将练习结果写回画像。

推荐用户路径：

```text
完成资源学习
→ 做一组题
→ 学习效果评估
→ 更新画像
→ 调整学习路径
```

## 五、路由调整方案

### 5.1 保留现有可用能力

当前已实现的软件杯相关文件可以先不删除，只做入口与文案改造。

现有文件：

```text
app/sky/software-cup/page.tsx
components/sky/software-cup/software-cup-page.tsx
lib/software-cup/demo-service.ts
app/api/sky/student/profile/conversation/route.ts
app/api/sky/resource-generation/jobs/route.ts
app/api/sky/course-knowledge/search/route.ts
```

### 5.2 新增产品化路由

推荐新增：

```text
app/sky/cloud-mind/course-studio/page.tsx
components/sky/course-studio/course-studio-page.tsx
```

可先复用现有 `SoftwareCupPage` 的主体逻辑，逐步重命名和拆分。

### 5.3 处理旧路由

`/sky/software-cup` 不再作为主入口。

可选处理：

| 方式 | 说明 | 推荐 |
| --- | --- | --- |
| 重定向到 `/sky/study-lab` | 答辩旧链接仍可用 | 推荐 |
| 重定向到 `/sky/cloud-mind/course-studio` | 更靠近资源生成工具 | 可选 |
| 保留隐藏页 | 不在导航展示，作为备用演示 | 可选 |
| 删除 | 风险较高，暂不建议 | 不推荐 |

建议第一阶段保留隐藏页，第二阶段再重定向。

## 七、实施步骤

### 阶段 1：去突兀化

目标：立刻去掉“软件杯外挂感”。

任务：

1. 从顶部导航移除 `软件杯`。
2. 保留 `/sky/software-cup` 隐藏访问。
3. 将页面用户可见文案去比赛化。
4. 将 `软件杯演示闭环` 改为 `学习闭环`。
5. 将 `运行闭环` 改为 `生成学习方案`。

验收：

- 顶部导航不再出现 `软件杯`。
- UI 中不出现“软件杯”。
- 原演示页仍可访问。

### 阶段 2：云端智囊新增课程资源工坊

目标：让多模态资源生成成为云端智囊的一个自然工具。

任务：

1. 在 `/sky/cloud-mind` 工具列表增加 `课程资源工坊`。
2. 新增 `/sky/cloud-mind/course-studio`。
3. 复用现有资源生成 API：
   - `/api/sky/student/profile/conversation`
   - `/api/sky/course-knowledge/search`
   - `/api/sky/resource-generation/jobs`
   - `/api/sky/resource-generation/jobs/[jobId]/stream`
4. 页面默认课程为《人工智能导论》。
5. 资源生成完成后提供跳转：
   - `加入学习路径`
   - `去天梯工坊`
   - `问云翼助手`

验收：

- 云端智囊中能看到课程资源工坊入口。
- 能生成至少 5 类资源。
- 资源卡片显示来源和置信度。

### 阶段 3：首页画像前置

目标：让学习画像成为系统底座，而不是藏在深层页面。

任务：

1. 在 `/sky` 首页新增 `我的学习画像` 摘要卡片。
2. 空状态支持自然语言输入。
3. 已有画像时展示：
   - 薄弱点。
   - 强项。
   - 推荐学习方式。
   - 今日建议。
4. 按钮跳转：
   - `完善画像` → `/sky/learning/profile`
   - `生成课程资源` → `/sky/cloud-mind/course-studio`
   - `进入学习实验室` → `/sky/study-lab`

验收：

- 用户进入首页即可感知画像能力。
- 画像不再只是天梯工坊中的一个子页面。

### 阶段 4：学习路径接入课程资源

目标：避免重复造路径系统，让资源生成服务于已有学习路径。

任务：

1. 学习路径节点增加推荐资源入口。
2. 课程资源工坊生成结果可以被学习路径引用。
3. 学习路径节点可跳转云端智囊对应工具。
4. 学习效果评估结果能更新画像和路径建议。

验收：

- 学习路径不是孤立计划，而能关联生成资源。
- 做题/反馈后能影响后续推荐。

### 阶段 5：学习实验室完整闭环

目标：形成答辩时可展示的完整学习闭环，但不作为突兀的主导航。

任务：

1. 将 `/sky/study-lab` 定位为 `学习实验室`。
2. 去掉页面中的内部开发/比赛痕迹。
3. 接入：
   - 画像摘要。
   - 课程知识库。
   - 资源卡片。
   - 学习路径。
   - 安全审核。
4. 从首页和天梯工坊提供入口。

验收：

- 答辩时可用 `/sky/study-lab` 展示完整闭环。
- 普通用户也能理解它是学习工作台，而不是比赛专区。

## 八、答辩表达方式

不要说：

> 我们单独做了一个软件杯页面。

建议说：

> 我们没有把赛题要求做成孤立模块，而是把它融入天空课堂的核心学习链路中。学习画像作为全局底座出现在首页和天梯工坊；课程资源生成作为云端智囊的工具；学习路径和效果评估沿用天梯工坊；学习实验室用于展示从画像、知识库、资源生成到路径规划和安全审核的完整闭环。

可以用这张映射表讲：

| 赛题要求 | 产品落点 |
| --- | --- |
| 对话式学习画像 | 首页画像卡片 + 天梯工坊学情分析 |
| 多智能体资源生成 | 云端智囊 / 课程资源工坊 |

## 十一、最终判断

最合适的融合方式不是“把软件杯放进某一个栏目”，而是把它拆成项目原有产品能力的增强：

- **学习画像**：放到首页和天梯工坊，成为全局底座。
- **课程资源生成**：放到云端智囊，成为 AI 工具。
- **学习路径**：沿用现有天梯工坊能力，不重复建设。
- **完整闭环**：沉淀到学习实验室，作为答辩和高级工作台。
- **软件杯名称**：只保留在文档和提交材料中，不进入用户界面。

这样既能满足软件杯要求，又不会破坏天空课堂现有的信息架构。
