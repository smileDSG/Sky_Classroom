# 拟人陪伴 —— Live2D 宠物模型评估（更新版）

> 议题：主页想要"活"一点，现在的 SVG 小猫被认为丑，决定试 Live2D / VRM。
> 结论先行：**Live2D 已在本项目跑通（隔离预览页），技术可行、零重构、可逆回滚。** 唯一的硬约束是**模型文件本体**（好看的猫）需要合规可下载的来源 —— 我无法凭空生成 `.model3` / `.vrm`。

---

## 一、现状

- 拟人陪伴第一版 = 输入框旁一只 SVG 小猫（已上线，零依赖）。**观感不过关，被否。**
- Live2D / VRM 渲染引擎此前未接入；仓库零 `.model3` / `.vrm` 模型文件。

## 二、本轮实测结果（这台机器 / 实际网络环境）

| 环节 | 来源 | 可达性 | 说明 |
|---|---|---|---|
| 渲染引擎 | `oh-my-live2d` (npm) | ✅ 可安装 | 开源 MIT，SDK 内建 Cubism2/5，无需另配核心 |
| Cubism 运行时 | live2d.com（cubism SDK hub） | ✅ 可访问 | 库安装自带，不额外依赖 |
| 模型源 | GitHub raw（免费模型合集） | ❌ 超时 | 主来源原始机关，国内直连不稳 |
| 模型源 | model.oml2d.com（作者官方站） | ⚠️ 通但不稳 | HEAD 200，但大模型 GET 偶发超时，不适合当生产源 |
| ✅ 已解决 | **模型自托管进 `/public/live2d/`** | ✅ 已验证 | 黑猫 Hijiki + Tororo 已本地化，`/live2d/...` 走同源静态，零外网依赖 |

## 三、落地方案（符合"只做小组件、不重构"）

- 已新增**隔离预览页** `/sky/pet-buddy`：独立路由 + 独立小组件，**不碰首页、不改布局、不进主流程**，删一页即回滚。
- 模型走 `oh-my-live2d` 的 `loadOml2d`，支持本地 `/public/` 或远程 URL，一份模型 JSON 即可渲染（会呼吸、眨眼、待机动作）。
- 预览页现以**本地自托管的黑猫 Hijiki** 展示（另有 Tororo 备选）。模型文件在 `/public/live2d/`，`hijiki.model.json` + moc + 贴图 + 动作齐全，**浏览器走同源静态、零外网**，杜绝加载失败。
- 配套把 `/live2d/` 加入了 `proxy.ts` 的静态白名单（与 `/avatars/`、`/logos/` 一致），否则匿名请求会被鉴权代拦截、模型取不到。
- 想换更好看的猫：放一份合规的 `model.json` + 素材进 `/public/live2d/<name>/`，在候选列表加一条即可。

## 四、唯一的硬约束：模型文件本体

判断要诚实：Live2D/VRM 的好坏 90% 取决于模型本身，而 **`.model3`/`.vrm` 是外部美术资产，我这里生成不了**。要"更好看的猫"，需要其一：

1. **合规免费猫模型**（Live2D Cubism / VRM，作者允许商用或明确免费），由我方从可达渠道下载后放 `/public/` 自托管；或
2. **设计/授权一个专属模型**（通过 Live2D 官方 Cubism Editor 建模，或买授权），成本与版权再由产品定。
3. VRM(3D) 为备选，比 Live2D 重，猫类素材更少，**本轮先不并列投入**。

## 五、结论

- **Live2D 技术路线成立**：隔离预览页已能运行，可当场看效果、选模型。
- 下一步在**模型资源**：谁给一只合规的猫（或派谁找/画），我把它放进预览页替换即完成。VRM 本轮不排。
- 无重构、无架构改动、可一键回滚 —— 符合组长边界。
