# 摘星锦囊完善画像页面设计

## 背景

摘星锦囊首页已经有“学习画像”入口，并在用户画像不足时提示用户“完善画像”。当前入口指向
`/sky/learning/profile`，该路由实际承载的是天梯工坊的通用学习功能页，不是专门的画像补全流程。

仓库中已经存在较完整的画像能力：

- `/sky/student`：学情分析与学习处方页，适合展示画像结果和后续行动建议。
- `ProfileOnboardingChat`：对话式画像采集组件，可从自然语言中提取学习目标、薄弱点、偏好等。
- `/api/sky/student/profile/conversation`：画像对话 API，返回 `profilePatch`、证据和下一轮问题。
- `/api/sky/cloud-mind/personalization-context`：摘星锦囊、云端智囊等模块使用的个性化上下文。

因此，本次设计不从零创建画像系统，而是把现有能力组织成一个专门服务“完善画像”任务的页面。

## 问题

“完善画像”按钮的用户意图很明确：补充个人学习信息，让系统更懂自己。现有通用页或完整分析页都不能完全匹配这个意图：

- 通用学习功能页更像入口聚合，用户进入后不一定知道下一步该怎么完善。
- `/sky/student` 信息量较大，重点是“学情分析”和“学习处方”，不是第一次补全画像。
- 摘星锦囊首页的推荐、资源生成、练习和学习实验室都依赖画像质量，入口需要形成清晰闭环。

## 决策

将 `/sky/learning/profile` 设计为专门的“完善画像”页面，并复用现有画像采集、画像预览和推荐能力。

`/sky/student` 保留为完整学情分析页。完善画像页负责采集和确认；学情分析页负责诊断、处方和长期跟踪。

## 目标

- 用户从摘星锦囊点击“完善画像”后，第一屏就能开始补全画像。
- 页面明确展示系统已经识别了哪些画像信息，减少“我说的话有没有被系统理解”的不确定感。
- 完成补全后自然引导用户去生成资料、开始练习、进入学习实验室或查看完整学情分析。
- 复用现有组件和 API，避免重复实现画像抽取逻辑。
- 让页面可以在没有做题记录时也成立，先用对话画像启动个性化推荐。

## 非目标

- 不重写 `/sky/student` 的完整学情分析体验。
- 不重做画像抽取算法或引入新的后端模型链路。
- 不把“完善画像”做成设置页或账号资料页。
- 不要求用户一次性填写大量表单字段。
- 不改变摘星锦囊首页的信息架构，只修正“完善画像”的落点。

## 推荐方案

### 专门页面，复用现有能力

将 `/sky/learning/profile` 改造为画像补全工作台。

页面主体分为两列：

- 左侧：对话式画像采集。
- 右侧：实时画像预览与完成度。

底部或右侧下方提供下一步行动：

- 生成个性化资料。
- 开始智能练习。
- 进入学习实验室。
- 查看完整学情分析。

这是推荐方案，因为它最符合用户点击“完善画像”时的任务心智，也能最大化复用现有代码。

## 备选方案

### 直接跳转 `/sky/student`

优点是开发成本最低，可以复用完整页面。缺点是页面重心偏分析，用户可能觉得进入了“结果页”而不是“补全页”。当用户画像为空或很薄时，这个页面的说服力也会变弱。

### 继续使用现有 `/sky/learning/profile`

优点是改动最小。缺点是通用功能页不具备明确的任务完成感，也不利于承接摘星锦囊的个性化闭环。这个方案不推荐。

## 页面结构

### 顶部区域

顶部使用简洁任务导向标题：

- 标题：完善学习画像
- 副标题：告诉摘星锦囊你的目标、薄弱点和学习偏好，后续资源、练习和路径会按画像调整。
- 返回入口：返回摘星锦囊或返回天梯工坊。

顶部不做营销型大 Hero，保持工具型页面密度。

### 对话采集区

复用 `ProfileOnboardingChat`，但页面文案应更贴近“完善画像”：

- 首问聚焦“当前目标 + 最卡的地方 + 希望怎么学”。
- 支持用户用自然语言描述，不要求表单式填写。
- 每轮提交后展示系统提取到的关键信息和证据。
- 保留确认和修正能力，允许用户直接补充“不是这个，我其实是……”。

### 实时画像预览区

右侧展示当前画像字段：

- 学习目标
- 专业或背景
- 薄弱知识点
- 擅长方向
- 资源偏好
- 讲解偏好
- 学习节奏
- 当前状态

每个字段使用明确状态：

- 已识别：显示值和简短证据。
- 待补充：显示一句引导问题。
- 低置信度：允许用户确认或修正。

### 完成度与质量提示

页面可以计算轻量完成度，不需要复杂评分：

- 目标已明确
- 薄弱点已明确
- 学习偏好已明确
- 时间节奏已明确

完成度只用于引导，不作为阻断条件。用户信息不完整时也可以继续使用后续工具。

### 下一步行动

当画像至少包含“学习目标”或“薄弱点”之一时，展示行动区：

- 生成个性化资料：跳转 `/sky/cloud-mind/course-studio`
- 开始智能练习：跳转 `/sky/cloud-mind/quiz`
- 进入学习实验室：跳转 `/sky/study-lab`
- 查看完整分析：跳转 `/sky/student`

按钮文案应强调行动结果，而不是解释功能。

## 信息流

1. 用户在摘星锦囊首页点击“完善画像”。
2. 进入 `/sky/learning/profile`。
3. 页面加载已有个性化上下文，用于填充画像预览。
4. 用户通过对话补充学习目标、薄弱点和偏好。
5. `ProfileOnboardingChat` 调用 `/api/sky/student/profile/conversation`。
6. API 返回 `profilePatch`、证据、下一轮问题和确认状态。
7. 页面合并已有上下文与本轮 `profilePatch`，刷新画像预览。
8. 用户确认后选择下一步行动。
9. 下游工具继续通过个性化上下文获得画像信号。

## 组件边界

### 页面组件

`app/sky/learning/profile/page.tsx` 只负责路由入口，渲染新的画像补全页面组件。

### 新页面组件

建议新增 `components/sky/learning/profile-completion-page.tsx`。

职责：

- 加载现有个性化上下文。
- 持有对话返回的 `ConversationalProfilePatch`。
- 组合对话区、画像预览区、完成度和下一步行动。

### 可复用子组件

可以按需要拆分：

- `ProfileCompletionSummary`：画像完成度和关键字段状态。
- `ProfileFieldPreview`：单个画像字段预览。
- `ProfileNextActions`：完成后的行动入口。

这些子组件保持展示职责，不直接调用 API。

### 现有组件复用

`ProfileOnboardingChat` 继续作为对话采集入口。为了更适合专门页面，可以后续增加可选 props：

- `title`
- `description`
- `starterQuestion`
- `className`

这不是首版必需项。首版可以先复用现有默认文案。

## 状态与错误处理

### 加载状态

加载个性化上下文时，右侧画像预览显示骨架状态；对话区可以先渲染，不阻塞用户输入。

### 无画像数据

当用户没有任何学习记录和画像数据时，页面仍然正常可用。右侧字段显示待补充状态，并引导用户先描述目标和薄弱点。

### API 失败

对话 API 失败时，在对话区内展示错误并允许重试。页面不应丢失用户已输入内容。

### 数据不一致

如果已有个性化上下文与本轮对话提取结果不同，页面优先展示最新对话结果，并用“刚刚更新”标记。完整持久化策略保持后端现有逻辑。

## 视觉方向

页面应延续 Sky Classroom 当前的工具型风格：

- 清晰信息密度。
- 白色或深色半透明工作区。
- 绿色、天蓝色作为画像与成长语义的主强调色。
- 图标使用 `lucide-react`，例如 `UserCheck`、`Target`、`BookOpenCheck`、`Sparkles`。
- 避免大面积营销式 Hero，避免纯装饰性渐变和过多卡片嵌套。

移动端布局改为单列：

1. 标题
2. 对话采集
3. 画像预览
4. 下一步行动

桌面端使用两列：

- 左侧占主要宽度，用于对话。
- 右侧固定宽度，用于画像预览和行动入口。

## 测试策略

首版应补充聚焦测试：

- `/sky/learning/profile` 渲染专门页面，而不是通用 `LearningFeaturePage`。
- 页面包含对话画像入口。
- 对话返回 `profilePatch` 后，画像预览更新对应字段。
- 无画像数据时显示待补充状态。
- 下一步行动链接指向正确页面。

可选补充：

- 对话 API 失败时展示错误并保留页面。
- 已有 personalization context 能预填画像预览。

## 验收标准

- 从摘星锦囊点击“完善画像”后进入专门的画像补全页面。
- 页面第一屏能直接开始对话补全。
- 页面能展示实时画像预览，而不是只给用户一个聊天框。
- 用户补充信息后能看到学习目标、薄弱点或偏好被识别。
- 页面提供明确的下一步行动入口。
- `/sky/student` 仍作为完整学情分析页保留。

## 后续演进

首版完成后，可以继续增强：

- 将对话确认后的画像信号更稳定地写入用户画像存储。
- 在摘星锦囊首页显示画像完成度。
- 在云端智囊工具中展示“已按画像预设”的更具体原因。
- 支持用户手动编辑单个画像字段。
