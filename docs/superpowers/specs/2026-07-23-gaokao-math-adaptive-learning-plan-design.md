# 高考数学自适应学习计划系统设计规格

> 设计确认日期：2026-07-23
> 文档落库日期：2026-07-28
> 状态：产品方案已确认，待实施计划
> V1 对象：高中生、高三、高考数学冲刺
> 后续对象：大学生学习场景，不进入 V1

## 1. 目标

基于 `data/crawled/`、历史试卷、错题、拍照解题、测验、复习、学习计时和成绩记录，构建一个可解释、可执行、会随学习证据持续调整的个性化学习计划系统。

系统不是一次性生成一篇计划文章，而是形成闭环：

1. 收集并确认学习证据。
2. 更新知识点级掌握度、置信度和保持率。
3. 按确定性规则计算学习优先级。
4. 在时间、先修和资源约束下安排任务。
5. 每个学习事件后微调或完整重算计划。
6. 保存计划版本、调整证据和解释。

成功不只看分数，还同时衡量掌握度、延迟保持率和计划完成率。

## 2. 已确认的产品决策

1. 先服务高中生，大学生能力以后扩展。
2. V1 只覆盖高中数学。
3. 首个场景为高三高考冲刺。
4. 每个有效学习事件都进入动态闭环。
5. 冷启动先导入历史试卷和错题，再做自适应补充诊断。
6. 核心采用确定性规划、课程知识图谱和已验证 RAG。
7. LLM 只负责解释、摘要和措辞，不拥有最终调度权。
8. 不允许无关资源兜底；资源不足必须显式报错。

## 3. 当前基线与问题

### 3.1 抓取数据

`data/crawled/` 当前约有 5,641 个 Markdown 文件，约 43.6 MB：

| 分类 | 数量 |
|---|---:|
| 数学 | 915 |
| 英语 | 936 |
| 化学 | 787 |
| 生物、语文、物理 | 各约 500 |
| 学习方法、学习计划、课程大纲 | 各约 500 |
| 演示 | 3 |

已确认的数据问题：

- 至少 462 个额外重复来源文件，约 297 组重复标题。
- 数学数据主要来自 MathIsFun，正文以英文为主，跨度从小学到微积分。
- 目录标签不能可靠表达高考知识点、题型、难度和适用年级。
- `study-plans` 混有 GRE、留学申请、学前教育和泛教育内容。
- `syllabus` 多为新闻、政策或考试门户内容。
- 中文“数学 + 函数/导数 + 高考”查询可能召回生物资源。

结论：抓取数据只能作为待治理原料，不能直接进入学生计划。

### 3.2 现有代码

- `scripts/generate-learning-plan.ts` 使用关键词打分，并让 LLM 输出自由文本计划。
- `lib/mistakes/knowledge-graph.ts` 使用 `100 - mistakeCount * 20` 估算掌握度，未考虑证据质量、难度、置信度和遗忘。
- `app/sky/learning/page.tsx` 已有错题、复习、知识图谱和统计，但缺少统一的“智能计划”入口。
- 测验、错题、复习、计时和成绩尚未统一成可重放、幂等的学习事件。
- 个别同步失败被静默忽略，不适合可信个性化计划。

## 4. 范围

### 4.1 V1 范围内

- 高三高考数学课程知识图谱。
- 历史试卷、成绩和错题导入及确认。
- 自适应补充诊断。
- 学生画像和知识点级证据状态。
- 每日、每周计划生成与动态调整。
- 已验证数学资源索引和可追溯引用。
- 对接现有拍照解题、错题、测验、复习、计时和统计。
- 学生查看调整原因，教师审核歧义和锁定任务。

### 4.2 V1 范围外

- 大学课程、其他高中学科和初中课程。
- LLM 自主创建课程结构或自由修改调度规则。
- 未验证互联网内容直接进入计划。
- 自动保证正式高考分数。
- 多智能体自主协商式规划。

## 5. 总体架构

```text
抓取资料 -> 数据治理 -> 已验证数学资源索引 -------┐
课程标准 -> CurriculumPack / 课程知识图谱 --------┤
                                                    v
历史试卷/错题 -> 导入确认 -> LearningEvent -> 知识状态引擎
拍照解题/测验/复习/计时 --------------------------┘
                                                    |
目标、考试日期、可用时间 --------------------------v
                                            确定性规划引擎
                                                    |
                         ┌--------------------------┼--------------------┐
                         v                          v                    v
                    每日学习任务                调整记录           资源与解释
                         └----------------> 智能计划界面 <-------------┘
```

核心模块：

1. 数据治理与已验证资源索引。
2. 高考数学 `CurriculumPack`。
3. 学生画像与知识状态。
4. 确定性优先级和约束调度。
5. 已验证 RAG 与受限 LLM。
6. 统一 `LearningEvent` 与版本化重规划。

## 6. 数据治理与资源索引

### 6.1 治理流程

每个抓取文件依次经过：

1. 解析 front matter、正文、来源 URL、抓取时间和文件哈希。
2. 统一编码、标题、URL、语言和正文结构。
3. 使用规范 URL、内容哈希和文本相似度去重。
4. 严格判定学科；不确定项进入复核队列。
5. 标注年级、考试体系、知识点、题型、难度和资源类型。
6. 映射至少一个课程节点；歧义项不得自动通过。
7. 检查正文完整性、公式可读性、答案一致性和来源可信度。
8. 发布资源状态。

### 6.2 资源状态

| 状态 | 含义 | 可否用于计划和引用 |
|---|---|---|
| `verified` | 学科、课程映射、内容和来源均已验证 | 可以 |
| `needs-review` | 存在歧义或缺少必要字段 | 不可以 |
| `rejected` | 重复、跨学科、低质量、不适用或错误 | 不可以 |

只有 `verified` 资源可进入检索结果。缺少资源时返回 `RESOURCE_GAP`，包含缺失节点和期望资源类型，不得跨学科或放宽验证状态。

### 6.3 MathResource 契约

必填字段：

- `id`、`sourcePath`、`title`、`contentHash`。
- `subject = math`、`stage = senior-high`、`examSystem = gaokao`。
- `language`、`nodeIds`、`resourceType`、`difficulty`。
- `qualityScore`、`status`、`rejectionReasons`。
- 验证通过时记录 `verifiedBy` 和 `verifiedAt`。

所有契约使用严格 Zod Schema。Schema 无效必须报错，不能宽松解析后忽略字段。

## 7. 高考数学 CurriculumPack

课程包是版本化事实源，不从抓取文章自动推断。它至少包含：

- 课程版本、适用卷种和生效时间。
- 知识点树、别名和中英文检索词。
- 先修关系、相关关系和常见错误模式。
- 题型、典型难度、考试权重和建议活动。
- 掌握阈值、诊断题池引用和复习稳定性初值。

`CurriculumNode` 必须包含：

- `id`、`version`、`name`、`aliases`、`description`。
- `parentId`、`prerequisiteIds`、`relatedIds`。
- `examWeight`、`defaultStabilityDays`。
- `commonErrorCodes` 和允许的 `activityTypes`。

课程包发布前必须校验节点唯一性、引用完整性、别名冲突、权重范围和先修图无环。

## 8. 学生画像与知识状态

### 8.1 LearnerProfile

画像字段至少包括：

- `userId`、`stage = senior-high`、`grade = grade-12`、`subject = math`。
- `curriculumPackVersion`、`examDate`。
- `targetScore`、`latestScore`。
- `weeklyAvailableMinutes`、`dailyAvailability`、`preferredSessionMinutes`。
- `restDays`、`maxDailyMinutes`、`teacherLockedNodeIds`。
- `createdAt`、`updatedAt`。

个性化计划必须绑定认证用户。考试日期、目标分、可用时间或教师锁定项变化时触发完整重算。

### 8.2 KnowledgeState

每个学生、每个课程节点保存：

- `alpha`、`beta`、`mastery`、`confidence`。
- `retention`、`reviewStabilityDays`。
- `repeatedErrorCount`、`evidenceCount`。
- `lastEvidenceAt`、`lastReviewedAt`、`version`。

### 8.3 掌握度

使用 Beta 分布，初始先验：

```text
alpha = 2
beta = 2
mastery = alpha / (alpha + beta)
confidence = min(1, max(0, (alpha + beta - 4) / 12))
```

证据权重考虑：

- 题目难度和评分质量。
- 是否使用提示及提示强度。
- 作答耗时是否异常。
- 客观正确率或分步得分。
- 证据是否经教师确认。

正确证据增加 `alpha`，错误证据增加 `beta`。更新必须是纯函数、可重放并有单元测试。

遗忘保持率：

```text
retention = exp(-daysSinceReview / reviewStabilityDays)
```

成功的延迟复习增加稳定性，失败复习降低稳定性。证据不足应表达“不确定”，不能直接判定为不会。

## 9. 统一 LearningEvent

所有会影响计划的数据都写入统一事件，包括：

- `assessment-imported`
- `answer-submitted`
- `mistake-recorded`
- `review-completed`
- `task-started`
- `task-completed`
- `study-time-recorded`
- `teacher-correction`
- `profile-updated`

事件字段至少包括 `eventId`、`userId`、`type`、`occurredAt`、`source`、`nodeIds`、`payload`、`schemaVersion` 和可选 `correlationId`。

处理要求：

1. 以 `eventId` 幂等。
2. 重复事件返回 `DUPLICATE_EVENT`，不得重复累计证据。
3. 先校验、再写事件、再更新派生状态。
4. 派生状态失败时，事件不能标记为已应用。
5. 能从事件流重建知识状态和计划历史。
6. 同步失败必须显式展示并允许重试。

## 10. 冷启动与诊断

冷启动顺序：

1. 建立画像、考试日期、目标和可用时间。
2. 导入最近 2 至 5 份试卷、阶段测试或错题记录。
3. OCR 并结构化题目、得分、答案、用时和来源。
4. 映射课程节点；歧义项由学生或教师确认。
5. 基于确认后的证据初始化知识状态。
6. 对低置信度、高考试权重或高先修影响节点补充诊断。
7. 达到覆盖和置信阈值后生成首版计划。

诊断选题按信息增益、考试权重、先修影响、不确定性和预计用时排序。当关键节点达到置信阈值或达到时间上限时停止。

OCR、网络和模型瞬时错误最多重试 3 次并使用指数退避。Schema 无效、答案冲突和课程映射歧义不得静默忽略。

## 11. 优先级与调度

### 11.1 优先级公式

```text
basePriority =
  0.30 * masteryGap +
  0.25 * examWeight +
  0.15 * forgettingRisk +
  0.10 * prerequisiteImpact +
  0.10 * repeatedErrors +
  0.10 * uncertainty

priority = basePriority * urgencyFactor
urgencyFactor ∈ [1.0, 1.3]
```

各分量归一化到 `[0, 1]`：

- `masteryGap = 1 - mastery`。
- `examWeight` 来自课程包。
- `forgettingRisk = 1 - retention`。
- `prerequisiteImpact` 根据依赖节点数量和权重计算。
- `repeatedErrors` 根据近期重复错误并设置上限。
- `uncertainty = 1 - confidence`。
- `urgencyFactor` 根据距考试时间、目标差距和近期趋势确定。

保存公式版本、输入快照和分量，确保教师能够解释安排原因。

### 11.2 LearningTask

每个任务至少包含：

- `id`、`nodeId`、`type`、`title`、`objective`。
- `plannedMinutes`、`difficulty`、`resourceIds`。
- `successCriteria`、`status`、`scheduledDate`、`reasonCodes`。

任务类型限定为 `learn`、`worked-example`、`practice`、`review` 和 `diagnostic`。任务由规则模板生成，LLM 不得自由创建调度结果。

### 11.3 调度约束

- 每日总时长不超过当天可用时间和最大时长。
- 遵守先修关系和最低掌握阈值。
- 避免连续堆叠过多高认知负荷任务。
- 每周同时包含新学、针对练习、间隔复习和阶段检测。
- 临近考试提高高频题型、错题回访和整卷训练比例。
- 教师锁定、已完成和进行中任务不可被自动移除。
- 无已验证资源的任务不得发布。

### 11.4 LearningPlan

计划至少保存：

- `id`、`userId`、`version`、`status`。
- `generatedAt`、`validFrom`、`validTo`。
- `curriculumPackVersion`、`plannerVersion`。
- 画像快照、任务、每周目标、约束检查结果和证据事件 ID。

计划状态为 `draft`、`active`、`superseded` 或 `completed`。

## 12. 动态重规划

### 12.1 不变量

1. 已完成任务不可修改。
2. 进行中任务不可删除或改换知识点。
3. 同一事件只影响一次状态和计划。
4. 微调最多改变当天剩余任务的 30%。
5. 每次调整保存前后版本、触发证据和解释。
6. 新计划必须重新通过时间、先修、资源和锁定约束。

### 12.2 微调

单次任务完成、错题、复习结果、掌握度跨阈值或当天时间小幅变化通常触发微调。微调可改变剩余任务顺序、难度、练习量或复习时间，但不能突破 30% 上限。

### 12.3 完整重算

以下情况触发完整重算：

- 导入新的正式考试或模拟考试。
- 考试日期、目标分或每周可用时间变化。
- 教师修改课程映射或锁定约束。
- 同一关键节点持续失败。
- 计划长期无法完成。
- 课程包或规划器发生需要迁移的版本变化。

### 12.4 PlanAdjustment

每次调整至少保存：

- `previousPlanId`、`nextPlanId`、`mode`。
- `triggerEventIds`、`changedTaskIds`、`preservedTaskIds`。
- 规则证据：节点、原因码、调整前值和调整后值。
- 用户可读 `explanation` 和 `createdAt`。

## 13. 已验证 RAG 与 LLM 边界

检索流程：

1. 硬过滤 `subject = math`、`stage = senior-high`、`examSystem = gaokao`、`status = verified`。
2. 以课程节点 ID 为主检索键。
3. 别名和向量相似度只用于节点内排序。
4. 再按任务类型、难度和语言过滤。
5. 返回资源 ID、标题、来源、质量分和可引用片段。
6. 无结果时返回 `RESOURCE_GAP`。

LLM 可以：

- 把规则结果解释成学生易懂的语言。
- 摘要已验证资源。
- 改写任务标题和反馈。
- 根据结构化证据生成调整说明。

LLM 不可以：

- 新增课程节点、先修关系或考试权重。
- 引用检索结果之外的资源。
- 修改任务时间、顺序、难度或状态。
- 在资源、Schema 或同步失败时编造替代内容。
- 将未通过 Schema 的自由文本业务对象直接入库。

## 15. 前端体验

在 `/sky/learning` 增加“智能计划”并置为第一个标签，保留原有错题、复习、知识图谱和统计。

首次进入按状态展示：

1. 未建画像：填写考试日期、目标和可用时间。
2. 证据不足：导入试卷/错题或开始诊断。
3. 映射待确认：展示题目、候选知识点和置信度。
4. 已生成：展示今天任务、完成标准、时长和安排原因。
5. 有调整：展示触发原因、变化任务和保持不变的任务。

任务卡片至少显示知识点、任务类型、预计用时、难度、完成标准、验证资源、来源和安排原因。

网络、同步、资源缺口或约束冲突必须明确显示影响范围和重试/处理入口。本地未同步事件不能伪装成云端已保存。

## 16. 教师能力

教师可以：

- 查看画像、证据覆盖、掌握度、置信度和保持率。
- 审核导入题目和课程节点歧义。
- 查看优先级分量和调整依据。
- 锁定知识点、任务、日期或最低学习量。
- 修正答案、难度和资源状态。
- 覆盖系统建议，并生成 `teacher-correction` 事件和审计记录。

教师修改优先于自动规则，但仍需通过数据、时间和资源约束校验。

## 17. 安全与审计

- 个性化数据仅对认证且获授权的用户开放。
- API 校验资源所有权，禁止跨学生读取。
- 日志不记录密码、令牌或无必要的完整答卷。
- 状态更新、计划生成、教师覆盖和资源验证均保存版本、操作者和时间。
- 模型调用只发送完成任务所需的最小数据。

## 18. 失败策略

遵循“禁止降级 Fallback”原则：

| 类型 | 示例 | 策略 |
|---|---|---|
| 可重试 | 网络抖动、OCR 超时、LLM 限流 | 指数退避，最多 3 次 |
| 不可重试 | Schema 无效、课程图有环、逻辑冲突 | 立即失败并暴露阶段 |
| 需要确认 | 课程映射歧义、答案冲突 | 进入学生或教师确认 |
| 资源缺口 | 无已验证目标资源 | 返回 `RESOURCE_GAP` |
| 同步失败 | 事件未写入服务端 | 显示 `SYNC_FAILED` 并允许重试 |

只有明确标记为可选增强的视觉预览或非关键说明可以跳过，且必须记录日志。计划、资源引用、知识状态和事件写入不可降级。

## 19. 测试策略

实现必须遵循 TDD。

### 19.1 单元测试

- 所有 Zod Schema 的合法、非法和版本边界。
- 数据去重、学科隔离、课程映射和状态转换。
- Beta 更新、证据权重、置信度和遗忘公式。
- 事件幂等、重放和重复处理。
- 优先级分量、紧迫度和稳定排序。
- 时间、先修、锁定、资源和负荷约束。
- 微调 30% 上限和不可变任务。

### 19.2 集成测试

- 试卷导入到知识状态初始化。
- 诊断选题、停止条件和首版计划。
- 错题、测验、复习、拍照解题和计时桥接。
- 检索仅返回已验证高考数学资源。
- 计划版本、调整历史和教师覆盖。
- 同步失败、重试耗尽和资源缺口。

### 19.3 端到端流程

1. 高三学生登录并创建目标。
2. 导入历史试卷并确认歧义。
3. 完成补充诊断。
4. 获得一周计划并开始任务。
5. 提交正确答案、错题和复习结果。
6. 验证知识状态和当天任务微调。
7. 导入新模拟考试并验证完整重算。
8. 教师锁定任务。
9. 验证已完成、进行中和锁定任务保持不变。

### 19.4 负面场景

- “函数/导数/高考”不得返回其他学科。
- `needs-review` 和 `rejected` 资源不得被引用。
- 资源不足时不得生成不可追溯任务。
- 重复事件不得二次增加掌握度。
- LLM 非法输出不得入库。
- 未登录用户不得生成或读取个性化计划。

## 20. 试点指标与验收

试点目标：

- 已验证资源引用率：100%。
- 跨学科错误召回：0。
- 薄弱知识点正确率中位提升：至少 10 个百分点。
- 周任务完成率：至少 70%。
- 延迟复习保持率：至少 75%。
- 重复事件导致的重复更新：0。
- 已完成或进行中任务被自动改写：0。
- 有证据和解释的计划调整：100%。

V1 验收条件：

1. 课程包通过结构和无环校验。
2. 计划只使用已验证资源。
3. 试卷和错题可导入、确认并形成知识状态。
4. 固定输入产生稳定且满足约束的结构化计划。
5. 学习事件幂等更新状态并触发正确重规划。
6. 学生能查看任务、来源和调整原因。
7. 教师能审核歧义、查看证据并锁定任务。
8. 关键单元、集成和端到端测试全部通过。

## 21. 分阶段交付

### 阶段 1：可信数据地基

- 定义严格 Zod 契约和版本策略。
- 建立最小可用 CurriculumPack。
- 完成去重、分类、课程映射和审核流程。
- 建立已验证资源检索接口。

### 阶段 2：证据与知识状态

- 统一 LearningEvent。
- 接入现有学习功能。
- 实现掌握度、置信度、保持率和事件重放。
- 完成导入确认和补充诊断。

### 阶段 3：计划闭环

- 实现优先级与约束调度器。
- 实现版本、微调、完整重算和审计。
- 增加“智能计划”首标签。
- 完成教师审查和锁定能力。

### 阶段 4：验证与试点

- 完成数据质量回归和端到端测试。
- 小范围高三学生试点。
- 用真实数据校准权重，每次校准均版本化。

## 22. 大学生扩展

大学生版本复用事件、知识状态、规划、资源验证和审计框架，但必须使用独立 CurriculumPack、评价方式和目标模型。不得复制高考权重、卷种、诊断阈值或先修关系。

后续可支持课程考试、考研、编程技能、项目学习和证书备考。V1 只保留必要的扩展字段，不提前实现未确认的大学业务逻辑。
