## Step 3 — recognize API 端点测试（第 1 次运行 ❌ 失败）

**时间：** 2026-05-20 16:16

**被测文件：** `app/api/sky/solve/recognize/route.ts`

**测试方案：** 6 项端点测试，mock `callLLM` 和 `getModel`，用 `makeFile()` 构造 File 对象作为 FormData 输入。

**测试数据：** 同计划书 6 项（无图片/非法格式/超大文件/正常识别/含LaTeX/无视觉提供商）

| # | 输入 | 预期 |
|---|------|------|
| 1 | FormData 不含 image | 400 |
| 2 | GIF 文件 | 400（校验拦截） |
| 3 | 11MB PNG | 400（校验拦截） |
| 4 | 1KB PNG + mock 返回题目 | 200 |
| 5 | 2KB PNG + mock 返回含 LaTeX 文本 | 200 |
| 6 | 删除所有视觉 Key + PNG | 500 |

**测试结果：** ❌ 1/6 通过，5/6 失败

| # | 状态 | 实际 |
|---|:--:|------|
| 1 | ✅ | 400 正常 |
| 2 | ❌ | 期望 400，实际 500 |
| 3 | ❌ | 期望 400，实际 500 |
| 4 | ❌ | 期望 200，实际 500 |
| 5 | ❌ | 期望 200，实际 500 |
| 6 | ❌ | 期望 500 + "没有配置"，实际 500 + "图片识别失败" |

**失败原因：** Node.js `undici` FormData 解析器不认 `new File(Uint8Array)` 构造的文件对象。`req.formData()` 内部 WebIDL 校验 `webidl.is.File(value)` 失败，抛出 `AssertionError`，被 catch 捕获返回 500 `"图片识别失败"`。导致所有传入图片的测试（#2-#6）都无法进入业务逻辑，直接在 FormData 解析阶段崩溃。

**根因定位：** `makeFile()` 使用 `new File([new Uint8Array(size)], name, { type })` 直接构造 File，但 Node.js 的 File 构造函数期望第一个参数为 `BlobPart[]`，直接传 `Uint8Array` 可能不满足 WebIDL File 接口。

**修复方向：** 先创建 `Blob`，再将 Blob 作为 File 的内容源。或者 mock `req.formData()` 绕过 undici 解析器。
