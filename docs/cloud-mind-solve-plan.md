# 拍照搜题 · 提升方案

> 云端智囊六功能之一。本文是单一事实来源；相邻索引见 `cloud-mind-feature-upgrade.md`，语义匹配深挖见 `cloud-mind-solve-semantic-match-plan.md`。

## 0. 一句话定位
"给答案"型工具的留存分水岭是 **命中率 × 可信度**：命中率决定"快不快/用不用"，可信度决定"信不信/敢不敢用"。两端都是匹配与校验问题，不是数据量或花哨问题。

## 1. 现状
六功能里最接近成熟：
- 多模态输入（拍照/语音/文字）+ 低置信度人工确认
- SSE 流式：查库 → 路由 → 解题；后台作业轮询（切页不丢）
- 题库命中走"秒速响应"（TF-IDF / FULLTEXT+bigram，阈值 0.85）
- 批改 + 学情回流（掌握度变化）→ 自动进错题本 → 下一步衔接，骨架屏齐备

## 2. 短板与取舍
| # | 短板 | 取舍 |
|---|---|---|
| R1 | 无答案自校验，AI 算错就显示错答案（"给答案"工具最致命） | 不搞全量复核（费时费钱、抵消流式）。只对**可判定题**（选择/填空/判断，答案定值）用轻量独立复核，不一致则自动重试或标注"答案待确认"；开放解答跳过 |
| R2 | 题库命中靠文本相似度，OCR 噪声/表述差异一碰就断 | 匹配层升级（见 R4）+ 自沉淀，比纯爬库有效 |
| R3 | 爬版权题库 = 否 | 法律雷区 + 工程不兼容 + 与本产品自产/导入原则冲突 |
| R4 | 语义匹配能力缺失，只用文本相似度 | 见 `cloud-mind-solve-semantic-match-plan.md`：embedding + 进程内轻量向量检索，级联"哈希精确→文本快筛→语义 top-k→AI 兜底"；OCR 归一化是前置；走"相似题召回"而非重 RAG |

## 3. 优先级行动
| 优先级 | 事项 |
|---|---|
| P0 | 可判定题答案自校验（生成后独立复核，错则重试或标"待确认"） |
| P0 | 搜题成功结果回填 `question_bank`（规范化题目+答案+解析+知识点），与出题共用一张表 |
| P1 | 匹配层升级（语义匹配，见子文档） |
| P1 | 输入层 OCR 归一化（源头治理识别噪声） |

## 4. 测试方法
- **答案自校验（自动）**：构造"正确题 / 计算错题"，断言不一致时正确重试或标注"待确认"，绝不静默给错答案。
- **入库自沉淀（自动）**：搜题成功一次后查询 `question_bank`，断言出现该规范化题且带知识点；重复搜同题不重复入库。
- **命中率提升（人工/数字）**：用 OCR 噪声样本集实测命中率，升级前后对比，命中应对 ≥ X%（样例集阈值）。
- **正确性回归（自动）**：既有批改/学情回流/错题本用例不回归（部分已在线下，补无 mock 的 LLM 失败场景）。
