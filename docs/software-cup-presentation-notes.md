# 软件杯答辩讲解词

## 1. 开场定位

我们的系统定位是“面向高校专业课程的多智能体个性化学习资源生成系统”。它不是单纯的课件生成工具，而是围绕学生画像、课程知识库、多智能体资源生成、学习路径和效果评估形成闭环。

本次演示课程选择《人工智能导论》，因为它覆盖搜索、知识表示、机器学习、深度学习、大模型、智能体和 AI 安全，能很好体现赛题要求。

## 2. 课程知识库

我们自行构建了一套《人工智能导论》课程知识库，包含课程元信息、12 章课程大纲和讲义、48 个知识点的图谱、48 道初始题库、4 个代码实操案例、拓展阅读、视频脚本和评分标准。

这部分对应赛题第三组要求：至少一门完整高校专业课程的初始知识库/文档集作为系统输入。

## 3. 对话式学习画像

传统系统常让学生填表，我们这里让学生用自然语言描述背景、目标和困难。系统从对话中抽取 8 个画像维度：专业背景、学习目标、知识基础、认知风格、易错点、资源偏好、学习节奏和当前学习状态。

画像不是一次性填写，而是会根据练习结果、资源反馈和学习行为动态更新。

## 4. 多智能体资源生成

系统采用 Director + 多 Agent 架构。Director 负责任务拆解，画像 Agent 抽取学生特征，课程理解 Agent 检索知识库，资源设计 Agent 决定资源类型，然后由讲义、题库、思维导图、视频脚本、代码案例等 Agent 分别生成内容，最后由质量审核 Agent 做来源和安全检查。

演示中一次生成 6 类资源：讲义、PPT 大纲、思维导图、题库、RAG 代码案例、视频脚本，超过赛题要求的至少 5 类。

## 5. 个性化学习路径

系统不会把资源简单堆给学生，而是根据画像和知识图谱规划学习顺序。比如这个学生不懂过拟合、模型评估和 RAG，所以路径先补训练集/测试集，再学过拟合和评价指标，然后做 KNN/决策树实验，最后进入 RAG 课程问答助手项目。

每个路径节点都展示推荐理由，便于学生理解“为什么先学这个”。

## 6. 防幻觉与安全

生成内容必须先检索课程知识库，再绑定来源章节。质量审核 Agent 检查来源是否支撑结论，并给出置信度。无来源或低置信度内容不会被当作确定事实输出。

内容安全方面，系统会识别代写、隐私泄露、敏感违规和高风险建议。对于代写请求，系统会转化为学习辅导，提供提纲、思路和自查清单，而不是直接代做。

## 7. 产品体验

系统采用现代 AI 产品交互：流式输出、Markdown 渲染、多模态资源卡片、Agent 进度追踪和长任务异步生成。这样学生不会在等待 PPT 或视频脚本时看到空白页面。

如果现场模型或网络不稳定，系统也准备了 fallback 数据，仍能完整展示画像、资源、路径和审核结果。

## 8. 收束

整个演示链路是：自然语言输入 -> 学习画像 -> 课程知识库检索 -> 多智能体生成资源 -> 来源和安全审核 -> 个性化学习路径 -> 练习反馈 -> 画像更新。

这条链路覆盖赛题核心功能、产品体验、安全可信和课程知识库三组要求。
