## 一、拍照搜题（solve）

**现状**：六功能中最成熟。已有多模态输入、SSE 流式查库→路由→解题、后台作业轮询（切页不丢）、题库命中"秒速响应"、批改+学情回流、自动进错题本、下一步衔接。骨架屏加载态齐备。

**短板 / 取舍结论**：
1. **答案可信度**（"给答案"型工具最致命）——无答案自校验。取舍：不搞全量二次校验（费时费钱，抵消流式优势），只对**可判定题**（选择/填空/判断，答案是定值）用轻量模型独立复核，不一致自动重试或标注"答案待确认"；开放解答题跳过。
2. **题库命中率**才是"留人分水岭"，不是 AI 分析本身。取舍：把每次搜题成功的真实结果（规范化题目+答案+解析+知识点）喂回题库自沉淀，与出题共用题库表，双边命中互相喂养。
3. **爬版权题库 = 否**（法律雷区 + 与本产品自产/导入原则冲突）。

**匹配层升级**（已细聊，见"语义检索"小节）：
- 用 **embedding + 进程内轻量向量检索**（不引入真向量库，级联：哈希精确命中→文本快筛→语义 top-k→AI 兜底）。
- **OCR 归一化是前置**，向量前先把识别噪声洗净。
- 明确搜题走"相似题召回"，不做重 RAG；RAG 只在资源工坊/授课/出题引用教材处用。

## 二、PPT 课件生成

**结论**：差异化已立住（深空主题），缺的是"生成体验 + 导出即用 + 模板可用性"。
**重点问题 = 视觉"二十几年老模板感"**（非花哨，是工艺失败）。

**核心改造**（详见 `docs/ppt-master-design-plan.md`）：
- 现成模板**要用，但用"手工精品母版 + AI 填内容槽"**，不整份套第三方（版权 + 套不进 + 模板感）。
- 不爬版权商用模板（Web 拒绝，且工程不兼容 pptxgenjs 链路）。
- "现代学术"默认主题试点：思源黑体全替换 + 现代学术配色盘 + 6 套内页母版 + 双端渲染统一。
- 本项目应走"**参考开放授权(CC0/MIT)设计规范 + 自产母版**"，可合规炫酷。

**测试**：样式不变量断言（无雅黑宋体、标题≥36/正文≥24、3 色角色、列表≤4、留白≥1/3）+ 人工 A/B ≥7/10 + 文理应用三科冒烟 + 长内容自适应 + 既有回归。

## 三、记忆卡片（flashcard） ⭐刚对齐

**现状**：骨架和个性化比预期成熟——已有完整 SRS 间隔重复（±18/+6 熟练度→算下次间隔→`cloud_mind_memory_reviews` 表→due 到期复习入口）、生成前基于薄弱点/到期项/画像预填、教学投影注入、错题本导入、桌面+移动双端页面。
**缺的不是"闭环能力"，是"等待感 + 主动提醒 + 渲染 + 算法没测死"**。

**短板 / 取舍结论**：

| 优先级 | 事项 | 类型 |
|---|---|---|
| P0 | 移动端：3D 翻卡 + 接公式渲染 + 修长文本溢出 | 渲染 |
| P0 | 首卡流式/分批生成（等满 60s 太伤留存） | 性能 |
| P1 | 桌面端：修 `overflow-hidden` 翻转裁切隐患 + 标签 `text-[10px]` 字号 | 渲染 |
| P1 | 首页/智囊页顶部"今天 XX 张待复习"主动提示（现在要手动打开才复习） | 闭环 |
| P1 | 给 `spaced-repetition.ts`/`memory-cards-agent.ts` 补算法单测（闷雷，现无） | 质量 |
| 低 | `cache.ts` 进程内内存缓存重启即丢 → 暂不动（学生内容互异，命中非关键） | 性能 |

## 四、公式与数学符号渲染（六功能共享基建） ⭐刚对齐

**结论**：不坏在"没渲染"，坏在**健壮性与适配**。`components/ui/inline-math.tsx` 是共享组件，修好则搜题/出题/PPT 全受益。

**短板 / 取舍结论**：

| 优先级 | 事项 | 说明 |
|---|---|---|
| P0 | Web：公式解析失败不再秀红色报错，降级为可读纯文本/占位 | `throwOnError:false` 不抛异常→try/catch 兜不住→满屏红字；纯收益无 tradeoff |
| P0 | 块级公式加溢出/缩放容器，不撑爆固定高度卡片 | 现 `block text-center` 无 max-height/滚动/缩放，高公式溢出卡片 |
| P1 | 移动端接入 `InlineMath`（现手机端公式显示 `$x^2$` 原文） | 覆盖缺口 |
| P1 | 输入层做 OCR/公式归一化（源头治理） | 分隔符/Unicode 映射打补丁追不过海量 OCR 形态 |

> 关键边界：`InlineMath` 目标设为"容错地不崩、尽力渲染"，不追求"万能 LaTeX 解析"；OCR 噪声治理放输入层，不放渲染层。

## 五、智能出题（quiz） ⭐刚对齐

**现状**：已有 AI 生成选择题 + 题库抽题两种模式、学科/难度/知识点/数量选择、答题后写学情、个性化参数推导 + RAG + 学情注入、LLM 多层容错、缓存。底层 `question_bank` 表已支持 choice/fill/solve/judge 四题型，但上层只认真做了 choice。

**短板 / 取舍结论**：

| 优先级 | 事项 | 说明 |
|---|---|---|
| P0 | 接上填空/判断题型 | 底层表已支持四题型，上层未接；简答 AI 判分不稳可后置。与搜题/题库自沉淀联动 |
| P0 | AI 生成题成功后**回填题库** | 现状生完即弃、不攒资产；回填后同知识点可复用。需做去重 + "生成题/标准题"区分标记，与搜题自沉淀合并为同一套"题库越用越厚"机制 |
| P1 | 答题"订正闭环"：答错→看解析/进错题本/衔接复习 | 复用搜题/记忆卡已有的错题本+下一步衔接基建，低成本高收益 |
| P1 | 出题输出套 Zod schema 校验 | 现只有 try/catch+手动修复；符合项目"Zod runtime validation"规范，属规范债不直接影响用户 |
| P2 | 公式渲染收敛 | 出题用自带的 `solve/math-renderer.tsx`（带 LRU 缓存），与 PPT/记忆卡的 InlineMath 不一致，属"多组件各写各的公式渲染"蔓延，统一到公式渲染专项 |

> 与搜题联动：出题、搜题成功结果共用 `question_bank` 表，双边命中互相喂养。缓存粗糙（相同 topic 二次返回旧缓存）暂不优先。

## 六、智能授课（teaching） ⭐刚对齐

**定位定论（关键）**：云端智囊·智能授课（A）与主页课堂/教室（B）**不重复，是"生成→播放"上下游**：
- A = 个人化逐章微课（逐章卡片阅读、云端智囊画像驱动难度/节奏、learning path、按钮式 TTS），产出"教案+内容块"。独立教学引擎（前置诊断→计划→并发生成章节→to-classroom 转换）。
- B（`app/classroom/[id]`）= LangGraph 多智能体协作课堂（AI 老师/同学对话讨论、白板、slide/quiz/interactive/PBL 场景、播放状态机、内置连读 TTS）。
- A 完成后"转为课堂模式"（`to-classroom.ts` 把 chunk→slide）进入 B → **A 为 B 提供内容，B 是 A 的播放出口**。
- A 的独有差异化 = 个人化微课 + 智能诊断 + learning path；B 独有 = 沉浸多智能体协作。**A 不该去够"沉浸"，该把 A→B 衔接做顺**（替代原先"给 A 加自动连读"的错误建议）。

**短板 / 取舍结论**：

| 优先级 | 事项 | 说明 |
|---|---|---|
| P0 | **A→B 衔接做顺**（"转为课堂模式"一键无感、转换稳定） | 这才是 A 的变现出口；用 B 的连读 TTS+沉浸课堂替代"给 A 堆自动连读" |
| P1 | 随堂自动发问的平台化（讲完测完衔接，借错题本/下一步基建） | A 内轻量加 |
| P1 | 授课页 UI 直接测试补缺（`TeachingPage`/`TeachingPanel` 无直接测试，后端 `tests/teaching/` 15 个已较好） | 质量债 |
| P2 | 知识库 RAG 内容深挖（现无显式 RAG，内容靠画像+模板 prompt） | 后置专项 |

> 测试：`tests/teaching/` 15 个文件（planner/generator/adaptive/personalization/to-classroom 等）是六功能里最全；缺口在页面层。

## 七、性能横切基线（跨全功能） ⭐刚对齐

> 目标：把散落在各功能的性能短板收成一条可验收的统一基线，避免"各打一针、重复造轮子"。

**六维核对表（✓有 / ✗缺 / △可用但需升级 / ?未评估）**：

| 功能 | 首屏 | 流式/首内容 | 缓存 | 并发 | 超时降级 | 生成体积 |
|---|---|---|---|---|---|---|
| 搜题 | ✓骨架屏 | ✓SSE 流式 | △题库秒速命中佳 | ✓后台作业 | △后台轮询优 | ✓ |
| PPT | ✓ | ✗非逐页（顺序依赖） | ✗ | ✗四段串行 | △QA 重试 | ✗一次 10 页 |
| 记忆卡片 | ✓ | ✗等满 60s | ✗内存态 | ✗全量单次 | ✗60s 超时即失败 | ✗一次整套 |
| 出题 | ✓骨架 | ✗ | △有但粗糙（无 freshness） | ✗ | △重试×1 | △ |
| 智能授课 | ✓ | ✓SSE 轮询 | — | ✓章节并行 | ✓失败自动重试+手动 | ✓ |
| 资源工坊 | ? | ? | ? | ? | ? | ? |

**统一基线（一条线管住六功能）**：
1. **首内容可见标准**：任何生成型工具 ≤3s 内可见第一个结果（搜题靠题库秒速、其余靠流式/分批），否则出骨架屏。
2. **统一流式管道**：PPT/记忆卡/出题都接"首块先出、逐块追加"，复用同一套前端流式/SSE 组件（现搜题、授课各写各的 → 收敛）。
3. **统一缓存策略**：一次性把三个"内存态/粗糙"缓存（记忆卡、出题、PPT）收敛成带 freshness 与可选持久化的缓存层（在现有 `cache.ts` 上改造）。同时修出题"相同 topic 二次返回旧缓存、无 freshness"的正确性隐患。
4. **并发统一**：凡可拆的批量生成（记忆卡多张、出题多题、PPT 多页）都并行化。

**结论**：性能重灾区 = **PPT + 记忆卡片**（冷启动/等待感最差）；地雷 = **出题**（无 freshness 的正确性隐患）；搜题/授课最健康。

## 八、课程资源工坊（course-studio / resources） ⭐刚对齐

**现状**：支持 6 类资源（讲义/PPT/导图/题库/实操/视频脚本），生成后"阅读/复制/下载 Markdown"，2s 轮询恢复后台任务。流程：安全检查→画像构建→资料检索→资源生成→内容检查→学习路径。LLM 单次 `callLLM`（25s 超时、重试×1）。RAG 检索 `data/course-knowledge/ai-intro`。个性化来自输入+对话信号+学习记录。
**复用度低**：不共用 PPT 管线；与授课通过 `submitClassroomJob` 传上下文；与出题无共用。
**落她形式**：仅 Markdown 下载/磁盘 JSON 持久化，**未入库、未成为其它功能的 RAG 素材源**（本可供给授课缺的 RAG，闭环未形成）。

**短板 / 取舍结论**：

| 优先级 | 事项 | 说明 |
|---|---|---|
| **P0** | **生成失败绝不再静默降级到 demo 假资源**（`lib/software-cup/demo-service.ts`） | 现失败悄悄返回演示假料，学生拿到假讲义却不知情——比搜题"给错答案"更隐蔽，拷掉包。改"明确报错 + 允许重试"，无 tradeoff |
| **P0** | **先选类型再单生成**（现 6 类一次全生成） | 性能+体验双败：单线程串行、超时长难完成、用户只想要一样却等六样。与出题"先选题型"同逻辑 |
| P1/P2 | 打通资源工坊 → 授课/出题 的 RAG 素材供给（前置依赖上两条） | 让生成产物进可复用素材库，补授课缺的 RAG、出题引用；作为后续专项 |
| P1 | 流式 `/stream` 接口已 410 挂掉 | 性能基线第 3 条统一流式管道覆盖 |

**测试现状**：`tests/sky/course-studio-page.test.tsx`、`mobile-course-studio-entry.test.tsx`、`software-cup/llm-rag-generation.test.ts`、`student/resource-interactions-route.test.ts`。缺失：API 路由、Runner、Job Store、Quality Review、全链路集成测试。

## 九、全量收敛优先序（跨六功能汇总）

> 全局思路：把零散短板收成三条横切主线 —— **信任感（质量）· 等待感（性能）· 闭环感（产品）**。以下为已确认的 P0 行动清单，按"信任 > 等待 > 闭环"排序；每条含子文档指向。

### 信任感（质量，最优先——错答案/假货是留人杀手）
| 功能 | P0 行动 |
|---|---|
| 搜题 | 可判定题（选择/填空/判断）答案自校验，不一致重试或标注"待确认" |
| 资源工坊 | **失败绝不降级假货，改明确报错+重试** |
| 记忆卡片 | `spaced-repetition.ts` 补算法单测（闷雷） |

### 等待感（性能，见第七节基线）
| 功能 | P0 行动 |
|---|---|
| PPT + 记忆卡片 | 首内容 ≤3s 可见：流式/分批"首块先出、逐块追加" |
| 出题 | 修缓存 freshness（相同 topic 二次返回旧缓存）；接流式 |
| 资源工坊 | 先选类型再单生成 |
| 全功能 | 统一流式管道 + 统一缓存层 + 批量生成并行化 |

### 闭环感（产品，让人想用）
| 功能 | P0 行动 |
|---|---|
| 记忆卡片 | 到期待复习的主动提示（页面顶部"今天 XX 张待复习"） |
| 智能授课 | A→B 一键转课堂衔接做顺（用 B 的连读 TTS+沉浸课堂） |
| 出题 | 接填空/判断题型 + AI 出题成功后回填题库（"题库越用越厚"） |
| 搜题 + 出题 | 成功结果共同回填 `question_bank`，双边命中互相喂养 |

### 待专项（P1/P2，不进首批）
- PPT 现代学术母版（见 `ppt-master-design-plan.md`）
- 公式渲染健壮化（第四节点）
- 资源工坊→授课/出题 RAG 供给
- 多"多组件各写各的公式渲染"收敛

> **严格执行建议**：按"一个功能、P0 一条、逐条落地+测试验收"推进（符合用户"逐个解决问题"偏好），先做信任感的资源工坊"防假货"与搜题"答案自检"两条底线，再做性能与闭环。
