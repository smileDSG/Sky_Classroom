## 已确认的关键决策

| 决策点 | 结论 |
|--------|------|
| **DP1 用户输入** | D（混合策略）：默认自动推断，点击"生成"后弹模板画廊确认 |
| **DP2 模板选择** | 12学科分类，弹窗展示全部12套封面缩略图，1套默认高亮，用户可自由切换 |
| **DP3 内容格式** | 统一结构化JSON Schema（见下文），AI只生成纯文本内容 |
| **旧主题系统** | 彻底砍掉现有的6套"天空蓝/极简白"等导出主题 |
| **目录编号** | JSON输出阿拉伯数字（01/02/03），后端按模板风格转换（一/二/三 或 壹/贰/叁） |
| **内容页适配** | JSON统一输出5个cards，模板按自身容量显示前N个（3-5个），多余丢弃 |
| **PoC范围** | 先验证2套差异最大的模板：现代几何风（最规整）+ 明快卡通风（最特殊） |

### 1.2 关键发现：完全统一的7页结构

**所有12套模板共享完全相同的页面类型序列：**

| 页码 | 类型 | 英文标识 | 内容特征 |
|------|------|----------|----------|
| P1 | 封面页 | cover | 英文标签 + 大标题 + 副标题 + 装饰 |
| P2 | 目录页 | toc | 标题 + 3个章节条目 |
| P3 | 章节过渡页 | chapter | 大数字 + "CHAPTER ONE" + 标题 + 副标题 |
| P4 | 内容页A | content_a | 英文标签 + 标题 + 多卡片/多步骤/分层内容 + 总结 |
| P5 | 内容页B | content_b | 英文标签 + 标题 + 特色内容（图文/卡片/列表）+ 总结 |
| P6 | 表格页 | table | 英文标签 + 标题 + TABLE + 总结 |
| P7 | 结尾页 | end | 英文结束语 + 中文大标语 + 副标语 + 装饰 |

**这意味着**：页面类型识别不需要AI判断，直接按索引映射即可。

### 1.3 每页结构的详细映射分析

#### P1 - 封面页 (Cover)

**统一的字段模型**：
```json
{
  "en_tag": "英文小标签，全大写，2-4个单词",
  "title": "中文大标题，4-8个字",
  "subtitle": "副标题，15-25个字"
}
```

**模板差异**：
| 模板 | en_tag位置 | title位置 | 是否有装饰图形 |
|------|-----------|-----------|---------------|
| 古典书香 | (4.7, 2.8) 居中 | (3.3, 3.5) 居中 | 印章图形(8.2, 6.2) |
| 商务专业 | (1.1, 3.3) 左对齐 | (1.1, 3.9) 左对齐 | 右侧色块装饰 |
| 明快卡通 | (无) | (2.6, 4.7) 居中 | 左上+右下圆形装饰 |
| 现代几何 | (1.1, 3.3) 左对齐 | (1.1, 3.9) 左对齐 | 右侧几何图形 |

**适配策略**：
- `en_tag` 为空的模板（如卡通风）→ 不显示英文标签，或隐藏对应文本框
- `title` 和 `subtitle` 为必填，所有模板都有对应位置
- 装饰图形（无文字的shape）→ 保留不动

#### P2 - 目录页 (TOC)

**统一的字段模型**：
```json
{
  "toc_title": "目录标题（如'目录'、'学习导航'）",
  "items": [
    { "num": "01", "title": "章节标题≤6字", "desc": "描述≤15字" },
    { "num": "02", "title": "章节标题≤6字", "desc": "描述≤15字" },
    { "num": "03", "title": "章节标题≤6字", "desc": "描述≤15字" }
  ]
}
```

**模板差异**：
| 模板 | 布局 | 编号样式 | 条目数 |
|------|------|---------|--------|
| 古典/商务/科技 | 纵向列表 | 汉字/圆圈数字 | 3 |
| 卡通/运动 | 三栏卡片 | 大号阿拉伯数字 | 3 |

**适配策略**：
- JSON统一输出阿拉伯数字 `num: "01"`
- 后端渲染时转换：
  - 古典风 → "一" / "二" / "三"
  - 商务风 → "1" / "2" / "3"
  - 卡通风 → "01" / "02" / "03"（保持大字号）

#### P3 - 章节过渡页 (Chapter Divider)

**统一的字段模型**：
```json
{
  "chapter_num": "01",
  "chapter_en": "CHAPTER ONE",
  "chapter_title": "章节标题",
  "chapter_subtitle": "章节副标题"
}
```

**模板差异极小**：所有模板都是左侧或居中展示：大数字(96pt) + CHAPTER ONE(14pt) + 标题(44pt) + 副标题(20pt)

**适配策略**：直接文本替换，四段文字的位置和字号在所有模板中高度一致。

#### P4 - 内容页A (Content A) —— ⚠️ 最大适配难点

**统一的字段模型**：
```json
{
  "tag": "英文标签，全大写，如 CONCEPT",
  "title": "中文标题，≤8字",
  "cards": [
    { "title": "卡片标题≤4字", "desc": "描述≤50字" },
    { "title": "卡片标题≤4字", "desc": "描述≤50字" },
    { "title": "卡片标题≤4字", "desc": "描述≤50字" },
    { "title": "卡片标题≤4字", "desc": "描述≤50字" },
    { "title": "卡片标题≤4字", "desc": "描述≤50字" }
  ],
  "summary": "底部总结段落，≤100字"
}
```

**各模板的P4卡片容量**：
| 模板 | P4结构 | 可容纳cards数 | 适配规则 |
|------|--------|--------------|----------|
| 古典书香风 | 5个横向图标卡片 | 5 | 显示 cards[0:5] |
| 商务专业风 | 5个纵向步骤 | 5 | 显示 cards[0:5] |
| 明快卡通风 | 3个大色块卡片 | 3 | 显示 cards[0:3]，cards[3:5]丢弃 |
| 活力运动风 | 4个横向图标卡片 | 4 | 显示 cards[0:4]，cards[4]丢弃 |
| 海洋探索风 | 4个分层区块 | 4 | 显示 cards[0:4]，cards[4]丢弃 |
| 清新自然风 | 5个2x3网格卡片 | 5 | 显示 cards[0:5] |
| 现代几何风 | 4个横向图标卡片 | 4 | 显示 cards[0:4]，cards[4]丢弃 |
| 田园复古风 | 4个横向卡片 | 4 | 显示 cards[0:4]，cards[4]丢弃 |
| 科技未来风 | 4个横向卡片 | 4 | 显示 cards[0:4]，cards[4]丢弃 |
| 简约北欧风 | 2个图表 | 2 | **特殊处理**：用cards数据生成2个简易图表 |
| 温暖人文风 | 4个横向卡片 | 4 | 显示 cards[0:4]，cards[4]丢弃 |
| 清新水彩风 | 4个色块卡片 | 4 | 显示 cards[0:4]，cards[4]丢弃 |

**关键决策**：
- JSON统一输出5个cards，按重要性排序
- Prompt引导AI把最核心的内容放在前3个cards
- 后端根据模板的实际容量截断（取前N个）
- 简约北欧风的P4是图表页，需要特殊处理：可以用cards的标题+数值生成2个柱状图/饼图

#### P5 - 内容页B (Content B)

**统一的字段模型**：
```json
{
  "tag": "英文标签，如 EXAMPLE",
  "title": "中文标题，≤8字",
  "cards": [  // 供卡片型模板使用
    { "title": "卡片标题", "desc": "描述≤80字" },
    { "title": "卡片标题", "desc": "描述≤80字" }
  ],
  "featured": {  // 供图文型模板使用
    "body": "大段文字内容，≤200字",
    "highlight": "关键句高亮，≤30字"
  },
  "summary": "底部总结，≤80字"
}
```

**各模板的P5内容区类型**：
| 模板 | P5内容区类型 | 使用的JSON字段 |
|------|-------------|---------------|
| 古典书香风 | 4个横向卡片 | cards[0:4] |
| 商务专业风 | 3个知识卡片(2x3网格) | cards[0:3] |
| 明快卡通风 | **左图右文** | featured.body + featured.highlight |
| 活力运动风 | 3个纵向卡片 | cards[0:3] |
| 海洋探索风 | 4个横向图标卡片 | cards[0:4] |
| 清新自然风 | **左图右文** | featured.body |
| 现代几何风 | 4个变换类型卡片 | cards[0:4] |
| 田园复古风 | 4个工具卡片 | cards[0:4] |
| 科技未来风 | 3个特性卡片 | cards[0:3] |
| 简约北欧风 | 2个知识卡片 | cards[0:2] |
| 温暖人文风 | 4个意象卡片 | cards[0:4] |
| 清新水彩风 | 4个配色卡片 | cards[0:4] |

**适配策略**：
- JSON同时提供 `cards` 和 `featured` 两种格式
- 后端根据模板类型决定使用哪个：
  - 卡片型模板（大多数）→ 使用 `cards`
  - 图文型模板（卡通风、自然风）→ 使用 `featured.body` 作为右侧文字，`featured.highlight` 作为高亮句

#### P6 - 表格页 (Table)

**统一的字段模型**：
```json
{
  "tag": "英文标签，如 DATA",
  "title": "中文标题，≤10字",
  "headers": ["列1", "列2", "列3", "列4"],
  "rows": [
    ["数据1", "数据2", "数据3", "数据4"],
    ["数据1", "数据2", "数据3", "数据4"]
  ],
  "summary": "表格下方总结，≤80字"
}
```

**各模板的表格列数**：
| 模板 | 表格列数 | 表格行数 | 适配规则 |
|------|---------|---------|----------|
| 古典书香风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 商务专业风 | 5 | 5 | 取 headers[0:5], rows[0:5] |
| 明快卡通风 | 3 | 4 | 取 headers[0:3], rows[0:4] |
| 活力运动风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 海洋探索风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 清新自然风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 现代几何风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 田园复古风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 科技未来风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 简约北欧风 | 3 | 4 | 取 headers[0:3], rows[0:4] |
| 温暖人文风 | 4 | 5 | 取 headers[0:4], rows[0:5] |
| 清新水彩风 | 4 | 5 | 取 headers[0:4], rows[0:5] |

**适配策略**：
- JSON输出标准4列数据
- 3列表格的模板 → 自动截断第4列
- 5列表格的模板 → 第5列留空或填"-"
- 行数不足 → 清空多余行（保留表格样式）
- 行数过多 → 截断

#### P7 - 结尾页 (End)

**统一的字段模型**：
```json
{
  "end_en": "THE END",
  "slogan": "中文大标语，6-10字",
  "subtitle": "副标语，15-25字"
}
```

**模板差异极小**：所有模板都是居中布局：英文结束语(14pt) + 中文大标语(44-48pt) + 副标语(20pt)

**适配策略**：直接文本替换。

## 第二部分：锁定的JSON Schema

```typescript
interface SlideContentPayload {
  // P1 封面
  cover: {
    en_tag?: string;      // 英文小标签，如 "RIGHT TRIANGLE"
    title: string;        // 中文大标题，如 "勾股定理"
    subtitle: string;     // 副标题，如 "探索直角三角形三边的奥秘"
  };

  // P2 目录
  toc: {
    title?: string;       // 目录页标题，如 "目录"（可为空，后端使用模板默认）
    items: Array<{
      num: string;        // 编号，如 "01"（后端按模板风格转换）
      title: string;      // 章节标题，≤6字
      desc: string;       // 章节描述，≤15字
    }>; // 固定3项
  };

  // P3 章节过渡页
  chapter: {
    num: string;          // 大数字，如 "01"
    en: string;           // 英文，如 "CHAPTER ONE"
    title: string;        // 章节标题
    subtitle: string;     // 章节副标题
  };

  // P4 内容页A
  content_a: {
    tag: string;          // 英文标签，如 "CONCEPT"
    title: string;        // 中文标题，≤8字
    cards: Array<{        // 最多5个，按重要性排序
      title: string;      // 卡片标题，≤4字
      desc: string;       // 卡片描述，≤50字
    }>;
    summary: string;      // 底部总结，≤100字
  };

  // P5 内容页B
  content_b: {
    tag: string;          // 英文标签，如 "EXAMPLE"
    title: string;        // 中文标题，≤8字
    cards?: Array<{       // 供卡片型模板使用
      title: string;
      desc: string;       // ≤80字
    }>;
    featured?: {          // 供图文型模板使用
      body: string;       // 大段文字，≤200字
      highlight?: string; // 关键句高亮，≤30字
    };
    summary: string;      // 底部总结，≤80字
  };

  // P6 表格页
  table: {
    tag: string;          // 英文标签，如 "DATA"
    title: string;        // 中文标题，≤10字
    headers: string[];    // 表头，建议4列
    rows: string[][];     // 数据行，建议4-6行
    summary: string;      // 表格下方总结，≤80字
  };

  // P7 结尾页
  end: {
    end_en?: string;      // 英文结束语，如 "THE END"
    slogan: string;       // 中文大标语，6-10字
    subtitle: string;     // 副标语，15-25字
  };
}
```

```

    │

弹出模板画廊模态框

    │

POST /api/sky/slides/generate
  Body: { topic, difficulty, templateId }
    │
    ▼
服务端：
  Step 1: 构建Prompt（注入JSON Schema + 字数限制）
  Step 2: 调用LLM生成JSON内容
  Step 3: 校验JSON格式 + 截断超长内容

  Step 7: 重新打包为PPTX
  Step 8: 可选：转换为PNG预览图
    │
    ▼
返回：{ success, slides, previewImages?, pptxUrl? }
```

## 第四部分：PoC实施计划

### PoC目标

验证2套模板（现代几何风 + 明快卡通风）的端到端流程：
```
topic="勾股定理" → AI生成JSON → 模板填充 → PPTX输出 → 人工检查
```

### PoC步骤

#### Step 1：建立字段映射表（现代几何风）

分析 `现代几何风教学模板.pptx` 的每页XML结构：
- 定位每个可替换文本框的 `<a:t>` 节点
- 记录：shape索引、段落索引、原始文本、字段名
- 输出：`modern-geometric.mapping.json`

#### Step 2：建立字段映射表（明快卡通风）

同上，输出：`cartoon.mapping.json`

#### Step 3：编写填充引擎原型

Python/Node脚本：
```bash
# 输入
- template.pptx
- content.json
- mapping.json

# 输出
- output.pptx
```

核心逻辑：
1. `unzip template.pptx -d unpacked/`
2. 读取 `ppt/slides/slide1.xml` ~ `slide7.xml`
3. 按 mapping.json 找到 `<a:t>` 节点并替换文本
4. `zip -r output.pptx unpacked/`

#### Step 4：人工验证

- 打开 output.pptx
- 检查：文字是否正确填入、格式是否保留、是否有溢出
- 记录问题，调整映射表或JSON约束
