# 主页微调方案 —— 只动小组件，不动布局，把"人味"做进来

> 约束（组长定的，这版更严格）：**不重构界面、不动布局**。只改小组件、单文件、可回滚，每处都能指认"它让哪一块不那么像机器"。

---

## 一、先给一个判断：什么是硬要的"人味"

产品的"大众化"不是一个组件丑，是**处处统一的后台语言**（每块都给一种颜色、每句话都是标签式说明）= 冷、没人味。

但要小心：**人味 ≠ 装饰，也不等于吉祥物 / emoji / 抖音感。** 人味的本质是三种"对人的在场感"：

> **① 记得你 —— 系统用你的数据跟我说话，而不是喊欢迎语。**
> **② 回应此刻 —— 界面状态跟着现实时间 / 我的输入 / 生成阶段走。**
> **③ 知道什么时候安静 —— 克制是温度，噪声就是 AI 味。**

这三条**全部落在文案 + 微行为 + 一个会动的小物件上，零布局改动**——这就是组长要的"人味但不重构界面"。

---

## 二、人味原则（组长看这一页就够了）

1. **记得你**：问候、空态、下次建议都从真实数据来，不说空话。
2. **回应此刻**：时间、打字、生成，哪一个在变，界面就跟一句。
3. **知道安静**：温度密度首屏 ≤ 2 处，其余藏起来；不刷屏、不抢注意力。
4. **一条红线的反例**：静态贴纸、弹窗问好、循环闪、"嘤～"这类腻语气——这些正是 AI 味，是我们要躲开的。

## 三、落地对照表（零布局，逐区微调）

| 区域（组件 / 文件） | 现在（冷） | 改成（人味 · 仅文案与微行为） |

## 四、输入框小猫（组长提议）—— 评估与落地

**评估**
- 方向对：输入框是主页人味最稀薄的点，给一个会反应的陪伴者，是单点里最高杠杆的"活"。
- 成败在**微反应**不在造型：必须"平时近乎隐身、动时才活"。做成静态贴纸 = 立刻退回 AI 味。
- 复用已有资产：项目有吉祥物 `小镜`（答疑助理）。这只猫定位为"主页输入框旁的小陪伴"，与它互不抢戏、不新建世界观。

**落地（单文件、零依赖）**
- 新建 `components/sky/home/input-cat.tsx`：内联 SVG（demo 资产可平移）三态 + `motion`；挂在 HeroInput 右下角，`pointer-events:none` 挡不了操作；CSS 变量取色、亮/暗都成立；`aria-hidden` + 可读 label；`git revert` 即回滚。

---

## 五、明确的"人味"黑名单（守住边界）

- ✗ 不用 emoji 堆砌 / 不弹窗跳出来打招呼 / 不循环聚闪动（噪声 = AI 味）。
- ✗ 不让角色抢戏：不挡按钮、不遮文字、不跳起来盖住输入框。
- ✗ 文案不上腻语气：温度靠"句句对你有用"，不靠"嘤～"。
- ✗ **不动布局与架构**：不重排 `page.tsx` 区块顺序、不引入"单一 Field / 镜头语法"等任何架构概念、只碰主页这几个小组件。

## 七、怎么判定"这一步到位了"（且不吵）

1. **色觉克制**：首屏主体色 ≤ 2 个（不再"每卡一色"）。
2. **首用无障碍**：3 秒内知道"这页面能干什么、哪里输入"。
3. **状态诚实**：没有 bug 级别的错误文案（如白天喊"晚上好"）。
4. **人味不吵闹**：首屏仍是安静的——静下来不打扰，只有当你动手时才有一点点活气。
5. **零副作用**：每个改动单文件、可 `git revert`，不影响 `/sky` 等其他页面。
