# 第 10 章 大模型与智能体

## 学习目标

- 理解大语言模型、Prompt、RAG、工具调用和智能体编排的基本概念。
- 能够描述一个 RAG 系统的核心流程。
- 理解多智能体协作在学习资源生成系统中的作用。

## 核心讲义

大语言模型（LLM）可以根据上下文生成自然语言、代码、表格和结构化内容。Prompt 是用户或系统给模型的任务指令和上下文。好的 Prompt 会明确角色、目标、输入、输出格式、约束和评价标准。但 Prompt 不能解决所有问题，尤其不能保证模型拥有最新、准确、可引用的课程事实。

检索增强生成（Retrieval-Augmented Generation, RAG）通过“先检索、再生成”降低幻觉风险。典型流程包括：收集文档、切分文本、计算向量表示、建立索引、根据用户问题检索相关片段、把片段作为上下文交给模型生成回答、输出来源引用和置信度。RAG 的质量取决于知识库质量、切分策略、检索召回率、重排序和生成约束。

智能体（Agent）在大模型基础上增加目标管理、工具调用、状态记忆和循环决策。一个学习资源生成系统可以设计多个智能体：画像分析 Agent 抽取学生特征，课程理解 Agent 检索知识库，讲义 Agent 生成解释，题库 Agent 生成练习，代码案例 Agent 生成实操任务，质量审核 Agent 检查来源和安全，学习路径 Agent 安排顺序。

多智能体架构的价值不在于“角色名字多”，而在于把复杂任务拆成可审计的步骤。每个 Agent 有明确输入、输出和责任边界，系统可以展示进度、保存中间结果、失败重试、人工复核和局部降级。

## 示例

学生输入“我不懂 RAG，想要代码案例”。Director 先调用画像分析 Agent 确认学生偏好代码和图解；课程理解 Agent 检索第 10 章 RAG 内容；资源设计 Agent 决定生成讲义、流程图、三道诊断题和一个课程问答助手案例；质量审核 Agent 检查是否有来源引用和低置信度内容。

## 常见误区

- 认为接入大模型 API 就等于完成智能体系统。智能体还需要状态、工具、流程和评价。
- 认为 RAG 可以完全消除幻觉。RAG 只能降低风险，仍需核验和拒答机制。
- 认为多智能体越多越好。角色要服务于任务拆解和质量控制。
